## 全局设置持久化：已保存模型在打开设置时本地恢复

**需求**：全局设置中保存的供应商连接和模型应永久保存为应用已有配置，启动后无需重新配置。

**核查结论**：
- 后端持久化本已完备：供应商连接（SQLite `provider_connections`）、模型定义（`model_definitions`）、模型绑定（`provider_model_bindings`）、API Key（Windows 凭据管理器，keyring 服务名 `com.infinitecanvas.desktop`）。
- 应用启动时 App.tsx 调用 `loadProviderCatalog()` 恢复生成节点模型目录，此路径无问题。
- **缺口**：ProviderSettingsDialog 打开时只加载供应商连接，不加载已保存模型——用户须重新点"拉取模型"（走网络）才能看到/编辑模型分类，造成"每次要重新配置"的感受。

**修复**（前端 3 文件，后端零改动）：
1. `src/lib/backend.ts`：`ProviderSettingsClient` 新增 `listSavedProviderModels(providerConnectionId)`，组合 `list_model_definitions` + `list_provider_model_bindings` 在前端映射为 `RemoteModelOption[]`（含 enabled=false 的显式禁用模型 → 显示为"不启用"）。
2. `src/features/settings/ProviderSettingsDialog.tsx`：
   - 新增 `restoreSavedModels(providerId)`（busyAction "restoring-models"，savedModelsRequestRef 防快速切换供应商的响应竞态，effect cleanup 时作废进行中请求）。
   - 对话框打开加载首个供应商后恢复其已保存模型；`selectProvider` 切换供应商时恢复；`handleSaveConnection` 保存连接后恢复（原为清空）。
   - 占位符条件改为 `busyAction == null`，文案更新为"已保存的模型在打开设置时自动恢复"。
3. `src/features/settings/ProviderSettingsDialog.test.tsx`：mock 补 `listSavedProviderModels`；新增 2 个用例（打开时本地恢复 + 直接保存；切换供应商时重新恢复）。

## 对象存储切换：Broker 中转 → 火山引擎 TOS 直连（AK/SK）

**需求**：对象存储改为直连火山引擎 TOS，AK/SK 鉴权，填桶名即可用；地域默认 cn-beijing，endpoint 默认 tos-cn-beijing.volces.com。

**方案决策**：
- 拒绝官方 Rust SDK `ve-tos-rust-sdk`（依赖 reqwest 0.11 + hyper 0.14，与项目 reqwest 0.12 双版本冲突、体积膨胀）。
- 拒绝保留 Broker 中转（需额外部署内部服务）。
- 采用：本地实现 TOS 签名 V4（官方文档 6349/129226 + 6349/74839），~150 行，仅新增 `hmac` 依赖；预签名 PUT/GET/DELETE URL 全部本地计算，上传/清理 HTTP 结构不变（cleanup_lease 无需改动）。

**改动**：
1. 新增 `src-tauri/src/backend/tos_sign.rs`：`uri_encode`（官方规则）、`TosCredentials::parse`（JSON secret）、`presign_url`（UNSIGNED-PAYLOAD，仅签 host）。单测含官方文档签名向量（signature=353aa555...，字节级匹配）。
2. `staging.rs`：`upload()` 移除 broker 请求改为本地 presign（PUT 15min / GET+DELETE 1h）；`validate_tos_config` 校验 bucket/region/endpoint/credential_ref；`build_object_key` scope 改为 bucket:region:endpoint。
3. `types.rs` `TosStagingConfig`：region/endpoint/bucket/credential_ref/object_prefix/enabled（camelCase 序列化）。
4. `storage.rs` `get_tos_config`：旧 broker 格式配置反序列化失败时降级为 None + warn（用户需重新填写直连配置）。
5. 前端 `TosStagingSettings.tsx`：桶名/地域/Endpoint/对象前缀/AK/SK 表单；AK/SK 以 JSON `{"accessKey","secretKey"}` 存凭据管理器（ref 固定 `tos-ak-sk`），两者留空沿用已保存凭据。
6. `docs/integrations/tos-staging-design.md` 升级 v0.9 直连架构。

**验证**：cargo fmt/clippy/test 39 全过（含官方签名向量）；tsc 双项目 / eslint 0 警告 / prettier / vitest 55 全过。
**工程细节**：`.prettierignore` 追加 `.firecrawl/` 与 `.workbuddy/`（非源码目录）；redact_url_string 已整体脱敏 `X-Tos-*` 查询参数，预签名 URL 可安全记日志。

## 保存配置后自动连通性测试（供应商 + TOS）

**需求**：点击"保存图片与视频模型"和"保存直连配置"后自动触发一次连通性测试，成功/失败都给用户提醒。

**设计**：
- 失败一律转换为 `ok=false` 的**结果**而不是错误（保存本身已成功，两种结果分开提示）；`reason` 为机器可读类别（network-error / auth-rejected / bucket-not-found / http-error / not-configured / credential-error），前端 `describeConnectivityTest()` 生成本地化中文文案。
- TOS 探测方式：对 `{objectPrefix}/.connectivity-probe` 预签名 GET（60s 有效期）。判定依据 TOS 先验签再查对象存在性：2xx 或 404+`NoSuchKey` = 通过；404 其他 = 桶不存在；401/403 = 凭据/签名被拒。

**改动**：
1. `types.rs`：`ConnectivityTestResult { ok, httpStatus, elapsedMs, reason, detail }`。
2. `provider.rs`：`test_connection()` 复用 `raw_json_request` GET `/v1/models`；辅助 `truncate_connectivity_detail`（400 字符截断，pub(crate) 供 staging 复用）、`connectivity_error_reason`。
3. `staging.rs`：`test_connectivity()`；`ProbeVerdict`/`classify_probe_response`/`extract_error_code`（XML `<Code>` 提取）+ 2 单测。
4. `commands.rs` + `lib.rs`：注册 `test_provider_connection`、`test_tos_connectivity`。
5. `backend.ts`：类型 + `describeConnectivityTest()`；两个 client 接口新增 `testConnection`/`testConnectivity`。
6. `ProviderSettingsDialog.tsx`：保存模型成功后 `busyAction="testing-connection"` 触发测试，横幅（settings-success/settings-error p）显示在 model-picker footer 下；切换供应商清空旧提示。
7. `TosStagingSettings.tsx`：保存成功且启用后触发测试（独立 `testing` 态，按钮显示"正在测试连通性…"）；停用保存跳过测试。

**验证**：cargo fmt/clippy 0 警告/test 41 全过；tsc / eslint 0 警告 / prettier / vitest 61 全过（新增 5 用例）。
**已知既有问题**：`App.canvas.test.tsx` 存在与本改动无关的偶发时序抖动（失败用例每次不同、单独复跑即过）。

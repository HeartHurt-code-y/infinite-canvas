## 修复 `pnpm tauri build` 打 MSI 失败（light.exe 退出码非零）

- 现象：Rust 编译成功（`src-tauri/target/release/infinite-canvas.exe` 已产出），
  但 `failed to bundle project: failed to run ...\WixTools314\light.exe`，tauri 吞掉了 light 的 stderr。
- 排障方法：手动复跑 light.exe 抓真实报错（tauri 的调用参数可从日志的 "Running light to produce ..." 推测）：
  `light.exe -dcl:high -ext WixUIExtension -out <out.msi> -b . -loc locale.wxl main.wixobj`
  - 不带 `-ext WixUIExtension` → LGHT0094（Unresolved reference to symbol 'Dialog:*'），这是假象，不是本因。
  - 带上扩展后暴露真因 → **LGHT0311**：`A string was provided with characters that are not available in the specified database code page '1252'`。
- 根因：`productName: "无限画布"` 是中文，而 tauri 默认 `bundle.windows.wix.language = "en-US"`，
  生成的 `target/release/wix/x64/locale.wxl` 为 `Culture="en-us"` + `TauriCodepage=1252`，中文字符不在 1252 码表内。
- 修复（`src-tauri/tauri.conf.json`，surgical）：
  ```json
  "bundle": { "windows": { "wix": { "language": "zh-CN" } } }
  ```
  重新生成 `locale.wxl` → `Culture="zh-cn"`、`TauriLanguage=2052`、`TauriCodepage=936`。
- 结果：`无限画布_0.1.0_x64_zh-CN.msi`（8.46MB）+ `无限画布_0.1.0_x64-setup.exe`（7.0MB）均产出成功。
- 注意：改 `tauri.conf.json` 会触发 tauri-build/codegen 重跑 + 重链接，release 构建约 5 分钟。
- 备选方案（未采用）：把 productName 改为 ASCII（如 InfiniteCanvas）——能根治但会改变产品标识与安装目录名。

## clippy 的 os error 5 告警：良性，非缺陷

- 现象：`warning: error copying object file ... libinfinite_canvas_lib-*.rmeta to incremental
  directory as ...\s-*-working\metadata.rmeta: 拒绝访问。(os error 5)`。
- 性质：**不是 lint**，故 `-D warnings` 不会提升为错误，clippy 仍 EXIT=0。cargo 会跳过增量继续编译，不中断。
- 根因：用户另有一个 **`pnpm tauri dev` 会话自 10:08 起在跑**（进程链
  explorer → powershell → pnpm tauri dev → cmd → node tauri.js dev → `cargo run --no-default-features`），
  应用 `infinite-canvas.exe` 存活。我的 clippy（dev profile）与 dev 会话共同竞争
  `target/debug/incremental`，`-working` 目录已被对方提交重命名，故拷贝被拒。
- 处理：**不杀进程**（属用户自己的 dev 会话）。也不必清 incremental 目录——
  停止 dev 会话后自然消失，属预期竞争而非故障。

## 副作用提醒

- build script 含 `cargo:rerun-if-changed=.../tauri.conf.json`，因此**每次改 tauri.conf.json 都会
  触发正在运行的 `tauri dev` 会话重新编译并重启应用**。改配置前留意用户的 dev 窗口会被打断。

<!-- ============ 它解决什么问题 ============ -->
<section style="padding:26px 22px 0 22px;">
  <p style="margin:0 0 6px 0;font-size:19px;line-height:1.6;font-weight:bold;color:#0f2b3d;">先说它解决的是哪四个真问题</p>
  <section style="background-color:#f7f5f0;padding:16px 18px;margin-top:12px;">
    <p style="margin:0 0 12px 0;font-size:15px;line-height:1.85;"><b style="color:#b3541e;">① 一致性会崩。</b>一部 20 段的短剧是<b>20 次独立生成</b>再拼起来的，段与段之间没有任何天然连续性。不给参考素材，同一张脸能逐段变成四个人。</p>
    <p style="margin:0 0 12px 0;font-size:15px;line-height:1.85;"><b style="color:#b3541e;">② 钱会白花。</b>一次批量就是几千币。提示词错了、段长装不下台词、参考图没上传——任何一个环节出问题，都是整批重做。</p>
    <p style="margin:0 0 12px 0;font-size:15px;line-height:1.85;"><b style="color:#b3541e;">③ 返工会反复发生。</b>同一件事的规则散落在四个文件里，改了一处漏了三处，还查不出来。</p>
    <p style="margin:0;font-size:15px;line-height:1.85;"><b style="color:#b3541e;">④ 出了问题没人发现。</b>最危险的不是崩，是「命令跑成功了、报告 20/20 成功」，而出片根本不能用。</p>
  </section>
  <p style="margin:14px 0 0 0;font-size:15px;line-height:1.85;font-weight:bold;color:#0f2b3d;">这套流水线的全部设计，都是围绕这四件事来的。</p>
</section>

<!-- ============ 特点二 ============ -->
<section style="padding:34px 22px 0 22px;">
  <p style="margin:0 0 10px 0;font-size:19px;line-height:1.6;font-weight:bold;color:#0f2b3d;border-left:4px solid #d94f2b;padding-left:10px;">特点二 · 一致性第一位：默认就是多参</p>
  <p style="margin:0 0 14px 0;font-size:15px;line-height:1.85;color:#5c5c5c;">整片是 20 段独立生成再拼起来的。唯一能把「同一个人、同一个场景」钉住的，就是<b>每一段都拿到同一套参考素材</b>。</p>

  <section style="background-color:#fff6f2;border:1px solid #f2d5c9;padding:16px 18px;">
    <p style="margin:0 0 12px 0;font-size:15px;line-height:1.7;font-weight:bold;color:#a8361a;">每段默认带上四样东西</p>
    <p style="margin:0 0 8px 0;font-size:14px;line-height:1.8;">🎭 <b>角色参考图</b> —— 脸 / 发型 / 服装（锁住「是谁」）</p>
    <p style="margin:0 0 8px 0;font-size:14px;line-height:1.8;">🏫 <b>场景参考图</b> —— 空间 / 色彩 / 光线方向（锁住「在哪」）</p>
    <p style="margin:0 0 8px 0;font-size:14px;line-height:1.8;">🔗 <b>上一段尾帧</b> —— 姿势与构图（锁住「接得上」）</p>
    <p style="margin:0;font-size:14px;line-height:1.8;">🎙 <b>角色音色样本</b> —— 用你锁定的声音，而不是模型随便找的（锁住「谁在说」）</p>
  </section>

  <p style="margin:18px 0 8px 0;font-size:15px;line-height:1.7;font-weight:bold;color:#0f2b3d;">这条是拿真金白银换来的</p>
  <p style="margin:0 0 10px 0;font-size:14px;line-height:1.85;color:#4a4a4a;">早期默认值把「多参」关掉了，于是整批 20 段以<b>零参考素材</b>提交：用户自带的角色图没用上、尾帧锚点没生效、音色没上传。结果是同一角色逐段换脸换发型（马尾 → 双辫 → 内扣短发 → 长直发）—— <b>20 段全废，3259 币</b>。</p>

  <section style="background-color:#0f2b3d;padding:16px 18px;">
    <p style="margin:0 0 10px 0;font-size:15px;line-height:1.7;font-weight:bold;color:#f2c14e;">于是立成铁律 D2-m</p>
    <p style="margin:0 0 7px 0;font-size:14px;line-height:1.85;color:#dff0f4;">① 默认必须走「一致的那条路」；会伤一致性的模式（纯文生视频）只能<b style="color:#f2c14e;">显式指定</b>，且进入时必须大声警告；</p>
    <p style="margin:0 0 7px 0;font-size:14px;line-height:1.85;color:#dff0f4;">② <b style="color:#f2c14e;">默认值必须与它指向的资源自洽</b>（默认文件是多参版，开关就不能是关）；</p>
    <p style="margin:0 0 7px 0;font-size:14px;line-height:1.85;color:#dff0f4;">③ <b style="color:#f2c14e;">命令示例不许把默认值偷偷换掉</b>——照示例敲命令，等于换了默认；</p>
    <p style="margin:0;font-size:14px;line-height:1.85;color:#dff0f4;">④ 拿不准时选「更贵但更稳」的那条：多参只多一次上传，却是一致性的唯一抓手。</p>
  </section>
</section>

<!-- ============ 特点三 ============ -->
<section style="padding:34px 22px 0 22px;">

  <p style="margin:0 0 14px 0;font-size:15px;line-height:1.85;color:#5c5c5c;">每改一次这套流水线，必须连过四道。任何一道不过，<b>拒绝发版、不写快照、不打 tag</b>。</p>

# 提示词引用规则

图片和视频生成节点共用以下规则。提示词生成节点的输入与输出仍是纯文本，导入媒体生成节点时才按目标节点的当前连接解释引用。

## 用户可见行为

1. 先连接素材，再输入 `@` 选择具体实例。也可输入 `@素材名` 或 `@图片2`；图片、视频、音频分别编号。
2. 普通文字保持原样。需要把裸素材名转成引用时，点击“识别素材名”。自动识别和按钮使用同一词典，不存在第二套绑定优先级。
3. 名称、文件名词干、编号命中多个实例时必须选择；编号与真实素材名撞名也一样。一次确认处理当前全部同名待确认项，之后输入仍独立判断。删掉一条连接不会替用户选择剩余对象。
4. 名称搜索、手动选择、输入、粘贴、上游文本导入和提交前校验共用规则。`参考图N / 图N` 等历史写法作为主编号的兼容输入保留；邮箱、URL、文件路径以及跨行文字不识别为引用。未匹配的 `@` 文字保留为文字，只有已绑定芯片才表示媒体引用。
5. 芯片绑定画布实例及来源身份。改名、编号变化不会改指向；断线、删除或来源替换会保留并标记失效，提交时阻止请求。已有 V1 结构化文档和旧 HTML 可读取；旧的选择记忆字段不再影响新文字。

## 编号和角色

全部连接按当前连线顺序形成唯一媒体清单，各类型从 1 独立编号。若先连接 A、B，正文写 `@图片2 @图片1 @图片2`，引用对应 B、A、B，实际上传清单仍是 A、B，各一次。

`explicitMedia` 保存全部实例的身份、角色、`typePosition` 与 `contentIndex`。提示片段只引用该清单，不从中移除已引用实例，也不重设首帧、尾帧等角色。同一来源的两个画布实例可以各占一个位置。

后端在媒体读取和联网前构造一次计划：验证位置从 1 连续、没有冲突、同类型编号与最终数组顺序一致，再按计划解析媒体。完全没有位置字段的历史请求保留原有首次引用顺序以便恢复；新任务采用固定连线顺序。

上游提示词按提示词连线身份和原始输出版本同步。素材连接变化不重复导入；保存恢复保留已编辑内容和已绑定身份。只有新建提示词连线或上游输出实际改变，才重新导入其文本。

## 代码入口

- `src/lib/promptReferences.ts`：纯数据词典、匹配、搜索、来源工厂与光标查询语法。
- `src/lib/promptReferenceTarget.ts`：来源身份解码与比较，供文档和编辑器共用。
- `src/lib/promptContent.ts`：节点文档、编辑会话、确认、快照及提交冻结。
- `src/lib/promptTiptap.ts`：原子芯片及文档投影，不解析业务名称。
- `src-tauri/src/backend/media.rs`：媒体计划校验、读取、角色及请求位置冻结。

回归测试覆盖默认与手动识别、同名与编号冲突、中文输入、鼠标键盘一致性、本地文件往返、断线、反向引用、角色保留和历史请求恢复。

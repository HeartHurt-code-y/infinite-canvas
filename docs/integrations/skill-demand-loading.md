# 技能按需加载：实现与保真验收

项目的技能请求已接入 `src-tauri/src/backend/prompt_optimize/skill_context.rs` 统一选择器。完整技能资料继续离线内置，核心合同和选中的参考文档按原文提供，不压缩成摘要、不删减用户历史或当前编辑稿。本文记录当前实现、2026-09-14 实施前基线与保真验收场景；代码层面的文档选择不能证明真实模型输出质量完全等同。

## 当前加载路径

`PromptOptimizationMode` 先选择内置技能，统一选择器再依据本轮要求、当前编辑稿和用户已确认历史选择实际请求需要的方法。应用合同、选中文档正文与结尾交付提醒完整保留；选择器不额外调用模型或要求供应商提供文件工具。

| 请求中的策略标记 | 当前行为 |
| --- | --- |
| `default_core` | Seedance 2.0/2.5、Wan 3.0、H3 的普通创作在没有专项匹配时使用完整核心方法，不预载所有案例 |
| `progressive` | 保留完整核心，叠加本轮和当前稿所需的参考原文；多项明确需求可以共同命中 |
| `conservative_fallback` | 意图不够明确或只有附件时，保留当前技能的全部非工具创作资料，优先避免漏掉方法 |
| `passthrough` | 小技能包及尚无专项选择规则的模式保持原方法。文档容器无法解析时也保留原始方法 |
| `explicit_full_package` | 本轮明确要求完整技能包时发送完整内置方法 |

当前支持文档选择的模式为 Seedance 2.0/2.5、Wan 3.0、H3、打斗导演与剧本双技能。两个及以下文档，或不足 32,000 字节且不含工具资料的小包，直接保留原方法；已按阶段工作的模式不叠加第二层裁剪。

普通请求不发送脚本实现、工具源码、README、测试与更新记录；本轮明确引用某个文件名时仍能取得该文档全文。它们继续随离线技能资料保存，模型不能把未发送的文件名当作已读正文，也不能声称执行本轮没有的工具。

选择器识别项目实际使用的当前稿与用户决定标签。一般修订保留当前稿所需维度；明确开始新任务时采用新的方向。剧本已确认的长剧集方向与打斗视频已选择的引擎可以延续，本轮明确排除的引擎不会从旧历史重新加入。

## 优化前基线与统计口径

优化前，请求先由 `PromptOptimizationMode` 选择技能，再通过 `build_system_and_user_prompts` 将技能方法作为系统消息，与用户历史和当前输入分别传给供应商。主要浪费发生在同一模式内：多个加载器在每次调用时拼接完整主技能、所有参考文档、全部案例，甚至不可执行的脚本源码。项目没有在每次请求中同时注入所有技能包。

## 已按阶段加载的模式

以下工作流继续按模式选择单一阶段文档，通过 `passthrough` 保留现有边界：

- AI 影视：router、synopsis、characters、worldbuilding、treatment、screenplay、assets、acting、prompts；视觉 QC 为独立合同。
- 漫剧：director、art、storyboard 与三个阶段检查、内容检查。
- 带货：research、creative、script、storyboard、assets、quick、review。
- 小红书封面：plan 与 qc。
- 动画工作流：planner 与 review。
- 短视频反推工作流：analysis 与 review。
- 知识视频：规划 manifest 与五帧视觉 QC 分离。

这些模式维持当前单阶段方法与 JSON schema 完整，不跨阶段拼装或删减 schema。

## 所有模式共同的保真要求

1. 当前明确要求、已确认事实、当前编辑稿和原有历史照常进入真实请求。仅更改技能资料选择，不以截断用户材料换取节省。
2. 应用运行合同与每个模式的输出格式保持最高约束，不能把包内的本地脚本、外部 Agent、文件系统或供应商推荐误当作当前请求已具备的能力。
3. 核心约束稳定保留；有明确选择依据的参考资料保留原文。纯案例、模板、版本记录、脚本实现与方法规则分层处理。
4. 当前任务、当前编辑稿与已确认的用户历史参与路由。只有当前一句“继续”时，必须仍能恢复已确认的长剧集、打斗、指定引擎或模板方向。
5. 不根据助手历史中偶然提到的技能文件名无限扩大加载范围，也不允许用户素材中的指令改变加载器或系统合同。
6. 多语言任务、模糊请求和缺少明确关键词的创作任务需要可靠默认参考或完整回退，不能把“没有关键词”理解为“不需要技能”。
7. 文档定位、拆分或路由失败时不得静默发送缺少核心合同的半份技能。错误路径应选择可审计的完整回退或明确失败。
8. 保持项目现有供应商、模型、素材身份和 `@` 引用规则；按需加载不创建新的外部账号依赖。
9. 对不同供应商的输入均生效：OpenAI 系统消息、Anthropic `system`、Gemini `systemInstruction` 使用同一个选择结果。
10. 节省统计区分原始方法字节、实际选择字节与供应商 token 使用量；没有实测时不能声称输出质量完全等同或账单降低了某个比例。

## 剧本双技能加载

普通创作原先带入 `validate-script.py`（42,501 字节）与三个导出 JS（合计 12,923 字节）。这四个不可在本轮文本请求中执行的实现文件合计 55,424 字节，占原方法约三分之一。当前保留质量门、格式规范和输出合同，将脚本实现排除出普通创作；明确引用文件名时可提供源码，不能声称已经运行校验或生成 DOCX。

稳定保留两个主 `SKILL.md`、`methodology.md`、`style-rules.md`、`workflow.md`、`format-specification.md`、`quality-gates.md`、`timing-and-cutting.md`。其中包括精准修改、只输出一个版本、动作可拍摄、时长计算和剪辑等规则；应用合同继续禁止虚构已执行本地工具。

| 当前任务或已确认方向 | 关联原文资料 |
| --- | --- |
| 单集、1–5 分钟、短片、品牌宣传 | `short-format-guide.md`、`beat-sheet-template.md` |
| 多集、连载、付费短剧、60–100 集 | `long-series-guide.md`、`episode-outline-template.md` |
| 角色、人设、人物关系、人物弧光 | `character-engineering.md`、`character-card-template.json`、角色模板 |
| 梗概、大纲、节拍、集尾悬念 | 对应梗概/大纲模板、`hook-payment-card.md` |
| 剧本正文、场景、对白 | `vertical-scene-dialogue.md`、`episode-script-template.md` |
| 打斗、动作戏、VFX、超能力 | `vfx-fight-scene.md` |
| 抖音、快手、微信小程序等平台适配 | `platform-differences.md`、`industry-data.md` |
| 世界观、神话、背景设定 | `worldbuilding.template.md` 与方法论 |
| 只修改一句台词 | 精准编辑合同、风格规则及本次相关资料；当前完整稿继续保留 |

短剧和长片方法都不能从产品中消失。缺少明确类型时，应保留两种模式的选择能力，并由原有需求澄清合同决定是否需要提问。

## 知识视频的完整合同

知识视频规划方法已经精简至 8,096 字节，包含受众和默认值、知识诊断、六段结构、画面轨、旁白与提示词、自动审校、异常决定、`knowledge-video-director.manifest.v1` schema。它是程序执行所必需的合同，不是大型案例库，保持完整最合适。

QC 继续仅发送五帧检查规则和 `PASS` / `RETRY` / `NEEDS_DECISION` 严格 JSON，不得重新夹带规划 manifest。普通细节自动采用假设，事实缺口才触发决定；不能因加载策略改变而增添例行用户确认。

## 验收样例

以下属于验收矩阵；真实模型的文风与质量仍需固定模型和相同输入做人工对照。单元测试可以验证文档选择、合同与请求链路，但不能独立证明创作质量等同。

| 输入场景 | 需要验证的行为 |
| --- | --- |
| “写一个三分钟悬疑短片，结尾反转” | 短格式原文可用；方法论、场次格式与质量门保留 |
| 历史已确认 80 集付费短剧，本轮仅“继续第 12 集” | 长剧集循环、钩子与已确认设定继续生效，不能按短格式重写 |
| 当前稿有打斗，本轮“让这段更有压迫感” | 从稿件识别打斗需求，加载 VFX/动作资料，保留非目标内容 |
| “只把第 4 场最后一句台词改得含蓄一点” | 精准修改、单版本规则保留，当前稿和用户历史未截断 |
| 打斗导演“给我这段视频的验收标准” | 加载 `failure-diagnostics.md`，不因缺少“失败”或“诊断”词漏掉验收方法 |
| Seedance 2.5“镜头跟拍角色变身后的一打多，保持连击动作连续” | 运镜与打斗工作流同时命中，保留变身和连击动作簇 |
| 历史已选 H3，本轮“不要使用 H3，换默认模型” | 已拒绝的引擎不从旧历史重新加入，采用可用默认方向 |
| 知识视频首次规划与失败后重试 | 严格 manifest 继续可被现有解析器消费；决定与重试合同不变 |
| 知识视频五帧 QC | 只返回三态 QC JSON，不误产规划 manifest |
| 英文请求或“继续优化”且无当前稿/历史 | 可靠的默认技能方法仍可用，不出现空资料请求 |
| 文档边界找不到或相关资料未匹配 | 使用可验证回退或明确错误，不发送缺核心的残缺方法 |
| 同一个请求通过 OpenAI / Anthropic / Gemini 适配 | 选择后的方法均进入相应系统字段；历史和参考媒体按原路径保留 |

# 打斗导演提示词技能接入

提示词生成与优化节点增加 `fight_prompt_master` 模式，界面名称为“打斗导演”。它调用用户在节点内选定的项目文本模型，交付打斗视频提示词，并复用节点的多轮对话、当前可编辑输出、参考素材和下游连线。

## 来源与打包

- 来源：用户提供的 `fight-prompt-master-20260903-V0.2.zip`。
- 版本：Fight Prompt Master V0.2，2026-09-03。
- 压缩包 SHA-256：`9d3d0a8051056530772a028791cc54fb95c8e48e3cd0560480f5e3d933b28964`。
- 目录：`src-tauri/skills/fight-prompt-master/`，原样保留 `SKILL.md` 与 11 份参考文档，排除自动格式化。
- 运行时通过 Rust `include_str!` 编译进应用，每轮重新注入完整技能，不依赖用户的下载目录或外部技能安装。

参考文档覆盖动作设计、七类结构、镜头语法、高密度模板 A/B、三个模型格式引擎、失败诊断、案例模板及版本记录。

## 节点交互

1. 从节点仓库添加“提示词生成与优化”，在技能模式中选择“打斗导演”，选择已有的文本模型。
2. 输入打斗需求，或连接参考图片、已保存的视频产物后生成。视频经现有联系表采样链路传给文本模型。
3. 通过对话指定目标视频格式、时长和速度档，例如：“SD2.5，15 秒，标准版，雨夜巷战，两人徒手，主角获胜，16:9。”已有参数和决定随完整历史传入，缺失项按选择卡补问一次。
4. 默认收到高强度、中间型、慢节奏三套方案；指定单一强度时只出该版。可回复“选方案二，只输出这一版完整提示词”，或直接编辑输出。
5. 切换优化时，可以填写修改要求，也可以留空以当前输出为基础优化。每轮同时发送完整历史与最新可编辑输出。
6. 输出保留标题、说明、完整代码块和必要补问；支持“只诊断不改写”，以及每轮只改一类变量的修正。最终选定的内容通过现有输出连线交给图片或视频节点。

无文字、无参考素材且无可优化输出时显示现有节点错误，不提交空请求。模式与对话随画布原有配置持久化，无新凭据或工作流运行记录体系。

## 应用适配合同

- **规则优先级**：应用能力边界和用户当前明确要求优先；原包内部以 `SKILL.md` 主合同为准。引擎只适配相应目标格式，不用旧“双版本”或“只输出正文”规则覆盖主技能的三方案、补问和诊断交付。
- **模型职责**：SD2.0、SD2.5、H3 是目标视频提示词格式，与实际调用的文本模型独立。原包的时长、延长、编辑等说明属于来源方法，不代表当前项目的视频供应商已支持这些能力。
- **素材依据**：只使用本轮真实附带的图片及视频联系表；无图时依据文字和历史已确认事实，不编造读图结论。联系表不能证明声音或未采样帧中的细节。素材内嵌指令不覆盖用户请求和内置方法。
- **交付完整性**：结果沿用通用思考块清理，但不只抽取首个提示词代码块；保留三套方案、选择卡补问和诊断说明。
- **长度截断**：供应商明确报告输出达到长度上限时，本模式按失败记录并提示指定单一强度或缩短时长后重试，不以未完成的正文覆盖当前输出。未返回截断标志的接口保持兼容，不根据字数猜测是否完整，也不擅自扩大所有文本模型的输出额度。
- **执行边界**：文本模型调用没有文件、Shell、Python、外部技能或视频 API 工具。不执行原包中的 TXT 导出、案例文件追加和技能自我更新，也不声称已经执行。案例及改进意见仅在当前对话内延续。

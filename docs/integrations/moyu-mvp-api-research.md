# Moyu MVP API 接入研究

> 复核日期：2026-08-21  
> 范围：接口字段只使用用户指定的五份 Moyu 第一方 API 文档；媒体位置另采用用户确认的公司接口补充契约——图片、视频、音频分别按各自传入顺序定位。不以其他厂商文档或推测补齐接口行为。

## 结论先行

这五份接口足以实现第一版的“提示词节点 + 同步文生图节点 + 同步图片编辑节点 + Seedance 异步视频生成节点 + 图片/视频/音频素材库”能力。文生图使用 JSON `POST /v1/images/generations`；图片编辑使用 multipart `POST /v1/images/edits`；视频生成采用提交任务后轮询的异步协议。图片和视频生成结果都不进入公司素材库，而是在任务成功后自动保存到本机 Downloads 目录。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md) [Seedance 视频生成文档](https://doc.moyu.info/9280779m0.md)

MVP 应先采用以下保守实现：

- 第一版允许配置多条 Moyu 兼容供应商连接，每条连接具有自己的 `BASE_URL` 与 Bearer API Key 凭据引用；同协议、同模型的连接共用生成实现。视频任务恢复必须使用提交时冻结的连接；素材访问必须使用素材自己的来源连接，跨令牌时不能直接复用 `asset://`。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md) [视频任务列表文档](https://doc.moyu.info/9280780m0.md) [素材库文档](https://doc.moyu.info/9280781m0.md)
- 所有生成节点统一创建本地异步任务，应用不设置业务并发上限或等待槽位；图片同步 POST 在 Tauri 后台并发等待，视频提交后独立轮询。网络错误与 HTTP `500–599` 在同一任务内按约 `2s/4s/8s` 自动重试最多 3 次并提醒用户，其他错误不自动重试。详见 [异步生成任务设计](../generation-task-design.md)。
- 所有成功、失败、未知和中断任务都跨应用重启持久保存，并能查看冻结参数、每次实际调用以及未经改写的完整原始返回；任务终态、节点删除或本地图片、视频文件缺失都不能清理历史。
- 保留现有“文生图节点”：唯一输入端口是必填提示词，节点内参数为供应商、模型、生成数量、`size` 和 `quality`。该 JSON 端点本身不接受参考图片。[文生图文档](https://doc.moyu.info/495380766e0.md)
- 提示词节点支持 `@` 结构化精确引用公司素材和本地生成结果，但这属于画布领域能力，不是 Moyu 的统一 `@` 协议。Task Module 必须先按稳定身份解析媒体，再根据目标端点编译；不能把 `@素材名` 字符串直接交给所有接口并声称已经传递媒体。
- 公司接口补充契约已确认：图片、视频和音频分别按各自的传入顺序区分位置，三个序列都从 `1` 开始，不存在跨类型共享的全局素材序号。提示内容依次出现图片 A、视频 A、图片 B、音频 A 时，位置分别是 `图片 1、视频 1、图片 2、音频 1`。
- 新接口应实现为独立的“图片编辑（图生图）节点”，而不是文生图节点里的模式。它具有必填、可重复且有顺序的图片文件数组端口、不同的 multipart 传输、必填模型和 Base64-only 输出；独立节点能让连线契约保持稳定，也避免切换模式后静默丢失图片输入。产品已决定 MVP 开放多图且采用前端轻校验，实际最大数量交给后端或供应商判断，不能从当前文档推断。[图片编辑文档](https://doc.moyu.info/497391425e0.md)
- “生成数量”保留在文生图、图片编辑和视频生成节点内部，但三类请求都没有数量参数。两类图片响应虽然是 `data[]`，文档没有说明如何请求条数；视频响应只展示一个 `content.video_url`。因此 MVP 的生成数量必须固定为只读值 `1`，同时图片解析器仍应容纳服务端意外返回的多项结果。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md) [Seedance 视频生成文档](https://doc.moyu.info/9280779m0.md)
- 新素材走 `POST /v1/assets` 的默认同步模式，传单个公网 `url` 和必填 `group_id`；取得真实素材 ID 后轮询 `POST /v1/assets/get`，素材进入 `Active` 后才允许连接到生成节点。[素材库文档](https://doc.moyu.info/9280781m0.md)
- 图片和视频生成成功后都不调用素材接口。图片 URL 或 Base64 结果保存为 `<Downloads>/无限画布/<safe(localGenerationTaskId)>-<resultIndex>.<实际扩展名>`；视频从 `content.video_url` 下载为 `<Downloads>/无限画布/<safe(task_id)>.<实际扩展名>`，不创建供应商子目录。历史预览只读取本地文件；TOS 只在本地结果以后作为必须使用公网 URL 的远程输入时按需中转。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md) [视频生成文档](https://doc.moyu.info/9280779m0.md)

## 认证、地址与隔离边界

所有已描述请求均通过 `Authorization: Bearer sk-...` 鉴权。文生图 OpenAPI 在操作层声明必需的 `bearerAuth`；图片编辑 OpenAPI 则把 `Authorization` 写成必填普通 Header 参数，同时把操作级 `security` 留空。实现上仍应统一发送 Bearer Header，不能依赖该文件的安全方案代码生成。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)

素材库文档明确素材、分组按令牌隔离，同一用户的不同令牌互不可见，历史 `token_id=0` 素材除外。[素材库文档](https://doc.moyu.info/9280781m0.md)

```http
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

两份图片 OpenAPI 都明确正式服务器为 `https://www.moyu.info`；另外三份文档只使用 `{BASE_URL}` 或 `http://localhost:3000` 示例，未正式声明它们是否也共享该服务器，也没有开发/测试环境地址。联调前仍应把各能力的基础地址做成配置，并由公司确认环境对应关系。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md) [Seedance 视频生成文档](https://doc.moyu.info/9280779m0.md) [视频任务列表文档](https://doc.moyu.info/9280780m0.md) [素材库文档](https://doc.moyu.info/9280781m0.md)

建议在产品领域层保存一个 `moyuCredentialId`，由安全存储解析出真实 API Key；生成节点、任务恢复和素材库访问都引用该凭据。API Key 不应写入画布 JSON、任务快照、日志或导出文件。这是客户端安全设计要求，不是文档已提供的密钥管理能力。

### 令牌隔离的产品含义

- 素材创建后只属于当前令牌及其分组；令牌 B 不能查看、修改或删除令牌 A 的素材。[素材库文档](https://doc.moyu.info/9280781m0.md)
- `asset://<ASSET_ID>` 虽然是稳定引用，但只在拥有该素材访问权的令牌作用域内有效。生成任务切换供应商连接后，不能把该字符串直接交给另一令牌；应使用素材来源连接刷新并下载字节或取得短期可读 URL，再按目标生成接口提交。[素材库文档](https://doc.moyu.info/9280781m0.md)
- `GET /v1/video/tasks` 也按当前令牌返回任务，且主动排除 Suno 音频任务与 Midjourney 图片任务；它不是全产品类型的统一任务列表。[视频任务列表文档](https://doc.moyu.info/9280780m0.md)
- 历史素材 `token_id=0` 在“全部素材”里可见，并可经 `POST /v1/assets/groups/transfer` 转移到指定令牌；新建素材不能写入历史分组 `id=-2`。[素材库文档](https://doc.moyu.info/9280781m0.md)

## 文生图模型与参数

文生图文档的描述声称支持 GPT-Image-2、豆包、Seedream、Gemini、Hailuo、即梦等系列，但没有列出可调用的精确模型 ID；请求示例中的 `model` 是 `gpt-image-1`，又与描述中的 GPT-Image-2 不一致。`model` 在 Schema 中不是必填，不传时使用一个未命名的默认模型。为了让生成结果可复现，MVP 不应依赖这个隐式默认值；模型选项必须来自公司确认的静态注册表或额外的模型列表接口。[文生图文档](https://doc.moyu.info/495380766e0.md)

### 图片响应结构

HTTP 200 响应 Schema 为：

```json
{
  "created": 0,
  "data": [
    {
      "url": "https://...",
      "b64_json": "..."
    }
  ],
  "usage": {}
}
```

`created` 是整数；`data` 是结果数组；每项可能包含 `url`、`b64_json`；`usage` 是未定义字段的空对象 Schema。所有响应字段和每个结果项的 `url` / `b64_json` 都没有标记为必填，也没有说明二者是互斥、至少一个存在，还是可能同时存在。因此解析器必须接受 URL、Base64 或两者同时存在，并把“结果项两者都为空”视为协议错误。[图片生成文档](https://doc.moyu.info/495380766e0.md)

文档没有声明 `url` 有效期、URL MIME/扩展名、`b64_json` 的图片格式、`created` 的时间单位或 `usage` 字段结构，这些信息不能作为当前领域模型的强校验条件。[文生图文档](https://doc.moyu.info/495380766e0.md)

## 图片编辑模型、输入与响应

### 节点形态决策：独立“图片编辑（图生图）节点”

MVP 应把 `/v1/images/edits` 实现为独立节点，而不是给现有文生图节点增加模式切换。两者共享图片结果领域对象和本地保存管线，但执行契约明显不同：[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)

| 差异       | 文生图 `/v1/images/generations`          | 图片编辑 `/v1/images/edits`                                                               |
| ---------- | ---------------------------------------- | ----------------------------------------------------------------------------------------- |
| 请求编码   | `application/json`                       | `multipart/form-data`                                                                     |
| 模型       | 可选，省略使用未命名默认模型             | 必填，示例 `gpt-image-2`                                                                  |
| 图片输入   | 该端点没有图片字段                       | 必填 `image[]` 文件数组                                                                   |
| 提示词     | 必填 `prompt`                            | 必填 `prompt`                                                                             |
| 可请求参数 | `size`、`quality`                        | 只定义 `model`、`image[]`、`prompt`                                                       |
| 结果媒体   | `url` 和/或 `b64_json`，字段存在性未保证 | `data[].b64_json`，没有 URL 字段                                                          |
| 输出元数据 | `created`、未定义结构的 `usage`          | 必填 `background`、`created`、`output_format`、`quality`、`size`、含三种 token 的 `usage` |

独立节点应显示必填图片端口，不能让用户在没有图片时误执行；它也允许将“文生图”与“编辑/合成多张图片”的意图直接体现在画布拓扑上。底层可以与文生图节点共用凭据、图片结果解析基类和本地结果保存模块。

### 模型与请求字段

接口为 `POST https://www.moyu.info/v1/images/edits`，请求使用 `multipart/form-data`，并显式要求 `Authorization: Bearer <API_KEY>` Header。[图片编辑文档](https://doc.moyu.info/497391425e0.md)

| multipart 字段 | 类型   | 必填 | 文档内容                            | MVP 映射                                                                                                 |
| -------------- | ------ | ---- | ----------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `model`        | string | 是   | 模型名称；唯一示例为 `gpt-image-2`  | 节点内必选模型；第一版可暂以 `gpt-image-2` 作为唯一候选，但必须通过真实环境验证                          |
| `image[]`      | array  | 是   | 图片文件数组；示例只含 `image1.png` | 必填、可重复、有顺序的图片输入；执行前把素材解析为文件字节，暂按有序重复 multipart part 构造并以联调确认 |
| `prompt`       | string | 是   | 编辑提示词；示例为合并两张图片      | 连接一个必填提示词节点，提交前校验非空                                                                   |

文档说明支持 GPT-Image-2、豆包、Seedream、Gemini、Hailuo、即梦等系列，但只给出精确示例 `gpt-image-2`，没有其他模型 ID、模型列表接口或逐模型能力；不得根据系列名拼接 ID。[图片编辑文档](https://doc.moyu.info/497391425e0.md)

图片编辑请求没有 `size`、`quality`、`background`、`output_format`、生成数量或其他编辑参数。响应虽返回这些元数据，但当前文档没有允许客户端设置它们，因此 MVP 不应把它们做成可编辑输入项。[图片编辑文档](https://doc.moyu.info/497391425e0.md)

### 图片输入限制

| 约束            | 文档已明确的事实                                                                          | MVP 处理                                                                          |
| --------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 数量            | `image[]` 必填且为数组，示例只有 1 个文件；未写最少/最多数量                              | MVP 开放至少 1 张的有序多图输入；前端不设最大数量，提交后展示后端或供应商真实错误 |
| URL             | 请求是 multipart 文件数组，没有 URL 字段，也没有 `asset://` 支持                          | 不直接发送 URL 或 `asset://`；素材节点先解析成文件字节                            |
| 格式            | 只出现示例文件名 `image1.png`，没有格式白名单                                             | MVP 至少实测 PNG；JPEG/WebP 等不得仅凭其他端点的规则推断                          |
| 大小            | 没有单文件、总请求体或像素尺寸限制                                                        | 客户端不能声称具体上限；需向接口方确认并用真实错误做契约测试                      |
| 文件字段 Schema | `image[]` 只有 `type: array`，没有 `items`、`format: binary` 或 part 的 Content-Type 规则 | OpenAPI 不能可靠自动生成客户端；手写 multipart 适配器并通过抓包/联调确认字段编码  |

如果图片来自 Moyu 素材库，适配器应先调用 `/v1/assets/get` 刷新可访问 `url`，下载图片字节，再把文件名、MIME 和字节作为 multipart part 发送；`asset://...` 不能直接放进 `image[]`。如果图片仍有本地原始文件，可直接读取本地字节，但任务快照必须保留素材 ID 与内容哈希，避免文件变化后请求不可复现。[图片编辑文档](https://doc.moyu.info/497391425e0.md) [素材库文档](https://doc.moyu.info/9280781m0.md)

### 同步响应与错误

图片编辑同样是同步 HTTP 200 响应，没有任务 ID 或状态查询。响应顶层把 `background`、`created`、`data`、`output_format`、`quality`、`size` 和 `usage` 全部标为必填；`usage.prompt_tokens`、`completion_tokens`、`total_tokens` 也全部必填。[图片编辑文档](https://doc.moyu.info/497391425e0.md)

```json
{
  "background": "opaque",
  "created": 1780036809,
  "data": [{ "b64_json": "iVBORw0KGgoAAAANSUhEUgAA..." }],
  "output_format": "png",
  "quality": "low",
  "size": "1024x1024",
  "usage": {
    "prompt_tokens": 88,
    "completion_tokens": 196,
    "total_tokens": 284
  }
}
```

`data[]` 的每个项只定义 `b64_json`，但该字段本身没有列入 `required`，所以空结果项在 Schema 上仍可能出现；解析器应要求至少一个非空 Base64 结果。响应没有 URL，图片结果必须先解码、验证，再原子保存为本地图片文件；保存阶段不使用 TOS 或素材接口。[图片编辑文档](https://doc.moyu.info/497391425e0.md)

文档没有定义非 200 响应、错误 JSON、请求超时、Base64 图片编码/格式校验、`created` 单位、结果数组数量、限流、价格或重试/幂等语义。[图片编辑文档](https://doc.moyu.info/497391425e0.md)

### 输出端口

- 文生图节点提供一个可承载多项结果的 `images` 输出集合。每个 `data[]` 项独立转换为一个候选结果；有 `url` 时下载到本地，只有 `b64_json` 时解码到本地。尽管输出是数组，请求端没有数量字段，因此节点的“生成数量”仍固定为 `1`。[文生图文档](https://doc.moyu.info/495380766e0.md)
- 图片编辑节点也提供 `images` 输出集合，但当前响应只定义 `data[].b64_json`；每个非空 Base64 项都解码并保存为本地图片结果，不进入 TOS 或素材库。请求同样没有数量字段。[图片编辑文档](https://doc.moyu.info/497391425e0.md)
- 视频成功响应只记录一个 `data.data.content.video_url`，所以视频生成节点提供一个本地 `video` 结果。应用使用远程 `task_id` 直接命名下载文件，不创建供应商子目录或 `VideoAsset` 素材记录。文档没有多结果数组或多输出数量字段。[视频生成文档](https://doc.moyu.info/9280779m0.md)

### 提示词中的 `@` 精确引用

Moyu 的五份文档没有定义统一的 `@mention`、素材别名或“提示词位置绑定媒体”字段。MVP 的 `@` 是本地结构化编辑能力：芯片保存公司素材的“来源供应商连接 + 素材 ID”，或本地结果的“生成任务 ID + 结果索引”；任务提交时解析为真实媒体并冻结内容哈希。

| 端点                     | 可编码方式                                                                                                                                                                                                                       | 不能承诺的能力                                                              |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `/v1/images/generations` | 只有字符串 `prompt`，没有任何媒体输入字段                                                                                                                                                                                        | 不能发送 `@` 媒体；含引用时必须在本地停止，不能丢弃引用或只发送素材名称     |
| `/v1/images/edits`       | `@` 图片先按出现顺序进入独立图片序列，显式图片端口随后按现有顺序追加；该序列映射为 multipart `image[]`，芯片在实际 `prompt` 中渲染为确定性 `图片 N`                                                                              | 文档没有序号/别名与文件 part 的正式绑定字段，不能保证模型理解某个自定义名称 |
| `/v1/video/generations`  | `@` 图片、视频、音频分别进入独立序列，再按协议映射到 `metadata.content`，使用默认 `reference_image`、`reference_video`、`reference_audio` 角色；混合内容的物理排列必须确定，且不能改变任一类型内部的相对顺序或把三类合成全局序号 | `@` 不自动推断首帧、尾帧、编辑或延长角色；文档也没有正式媒体别名字段        |

媒体位置与提示片段顺序是两个维度。结构化提示继续保留图片 A、视频 A、图片 B、音频 A 的文字出现先后；模型媒体位置则分别计算为 `图片 1、视频 1、图片 2、音频 1`。同类型内始终按当前连线顺序排列，`@` 引用查同一份媒体计划。首帧、尾帧、编辑源和延长源等特殊角色仍由显式端口或任务设置决定，但同样占用其媒体类型中的一个位置。

生成任务的实际请求视图必须同时展示：原始结构化提示、每个引用的稳定身份、提示出现位置、`mediaType + typePosition`、解析后的内容哈希、渲染后的字符串提示、图片/视频/音频三个实际输入序列和最终角色。签名 URL 查询串和凭据继续排除，但不能因此隐藏素材 ID、结果 ID、MIME、字节数或哈希。

“精确”在当前契约下表示对象、字节、同类型位置与请求映射精确可审计。公司已经确认同类型传入顺序是位置契约；但这不表示生成模型一定在创作结果中遵从自然语言别名。供应商若以后提供正式的媒体引用 ID 或别名字段，应在新 Adapter 版本中直接映射，而不改变提示词节点保存的结构化引用身份。

## 图片生成生命周期

文生图和图片编辑都只有同步 POST，没有远程任务 ID 或查询端点。产品仍为每次点击先创建独立本地异步任务，并在 Tauri 后台并发等待响应；本地状态使用 `created -> submitting -> succeeded/failed/unknown/interrupted`，但两个端点的成功结果校验不同：[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)

- 文生图：HTTP 200 且 `data[]` 至少一个结果项含非空 `url` 或 `b64_json`。[文生图文档](https://doc.moyu.info/495380766e0.md)
- 图片编辑：HTTP 200，所有文档要求的顶层字段存在，并且 `data[]` 至少一个结果项含非空 `b64_json`。[图片编辑文档](https://doc.moyu.info/497391425e0.md)

| 条件                                    | 本地状态      | 是否可恢复         | 处理                                                        |
| --------------------------------------- | ------------- | ------------------ | ----------------------------------------------------------- |
| 本地任务已持久化、请求尚未发送          | `created`     | 是                 | 立即启动独立后台执行，不等待其他任务                        |
| HTTP 请求已发出、尚未收到完整响应       | `submitting`  | 否                 | 展示生成中；产品不提供取消，进程意外中断也不等于服务端取消  |
| HTTP 200 且至少一个有效 `data[]` 结果项 | `succeeded`   | 已本地固化后可恢复 | 对每个有效项立即发起本地保存                                |
| HTTP `400–499`、解析失败或没有有效结果  | `failed`      | 仅错误快照         | 不自动重试；展示完整原始错误                                |
| HTTP `500–599`                          | `retry_wait`  | 当前进程内         | 按指数退避自动重试最多 3 次；每次完整保留原始响应并提醒用户 |
| 网络错误且无法确认远程是否执行          | `retry_wait`  | 当前进程内         | 按指数退避自动重试最多 3 次；提示可能重复生成和计费         |
| 应用退出中断等待，且没有远程任务 ID     | `interrupted` | 否                 | 重启后明确展示不可恢复，不自动重新提交                      |

由于两份图片文档都没有异步查询、任务列表、回调或幂等键，Task Module 只能提供应用运行期间的非阻塞后台异步。产品已决定对网络错误和 HTTP `500–599` 自动重试最多 3 次，因此同一任务可能产生最多 4 次远程请求并重复生成或计费；每次必须提醒用户并保留原始错误。应用退出后仍无法恢复尚未返回的图片请求，也不继续未完成的退避倒计时。要实现跨重启持久异步，必须增加公司后端任务执行层或取得供应商远程任务协议。产品不提供取消动作；进程退出导致本地等待中断时只能记录 `interrupted` 或 `unknown`，不能声称服务端生成已取消。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)

## 视频任务生命周期与状态映射

### 提交与单任务轮询

`POST /v1/video/generations` 返回 `task_id`；`GET /v1/video/generations/{task_id}` 的外层 `data.status` 是客户端应使用的标准任务状态，成功时结果位于 `data.data.content.video_url`，失败时读取外层 `data.fail_reason` 和内层 `data.data.error`。[视频生成文档](https://doc.moyu.info/9280779m0.md)

| API 状态      | 内部状态    | 用户含义                           | 处理                               |
| ------------- | ----------- | ---------------------------------- | ---------------------------------- |
| `NOT_START`   | `queued`    | 已提交、尚未开始                   | 继续轮询                           |
| `SUBMITTED`   | `queued`    | 已提交上游                         | 继续轮询；只在列表文档中出现       |
| `QUEUED`      | `queued`    | 上游排队                           | 继续轮询；只在列表文档中出现       |
| `IN_PROGRESS` | `running`   | 正在生成                           | 展示 `progress` 并继续轮询         |
| `SUCCESS`     | `succeeded` | 成功                               | 读取视频 URL 并立即下载到本机      |
| `FAILURE`     | `failed`    | 失败，也包含超时终止、余额不足终止 | 固化失败快照，允许用户显式重试     |
| `UNKNOWN`     | `unknown`   | 平台无法归类                       | 不视为成功或失败；提示用户稍后刷新 |

单任务文档只列 `NOT_START`、`IN_PROGRESS`、`SUCCESS`、`FAILURE`，而任务列表额外列出 `SUBMITTED`、`QUEUED`、`UNKNOWN`；统一状态机必须接受两份文档的并集。[视频生成文档](https://doc.moyu.info/9280779m0.md) [任务列表文档](https://doc.moyu.info/9280780m0.md)

文档没有取消状态或取消端点，产品也明确不提供取消、停止或暂停操作。关闭任务界面不停止后台轮询；退出应用只停止本地进程，远程视频任务仍继续并在重启后恢复。[视频生成文档](https://doc.moyu.info/9280779m0.md) [任务列表文档](https://doc.moyu.info/9280780m0.md)

### 任务恢复

应用重启后，通过 `GET /v1/video/tasks?start_timestamp=...&end_timestamp=...&p=1&page_size=100` 分页恢复当前令牌任务；要循环分页直到读取 `total`，并为每一项保留原始 `status`、时间、进度和 token 用量。[任务列表文档](https://doc.moyu.info/9280780m0.md)

任务列表的 `fail_reason` 有双重语义：`SUCCESS` 时它是视频代理 URL，`FAILURE` 时它才是失败原因。适配层可以按状态读取它来驱动结果或失败状态，但诊断接口必须保留并展示完整原始任务响应，不能只暴露拆分后的派生字段。[任务列表文档](https://doc.moyu.info/9280780m0.md)

占位失败任务的 `task_id` 可能为空串，而列表项没有另一个明确的任务记录主键。这样的记录不能可靠地和本地任务一一去重，应暂时使用令牌 ID、提交时间、状态等组合作为展示键，但需要服务端补充稳定 ID 才能彻底解决。[任务列表文档](https://doc.moyu.info/9280780m0.md)

## 素材库：分组、上传与状态

### 分组规则

- 创建任何新素材前都必须有 `group_id > 0`；系统不再自动创建默认分组。[素材库文档](https://doc.moyu.info/9280781m0.md)
- `GET /v1/assets/groups` 返回当前令牌的自定义分组；若有历史数据，列表开头还会有不可写的合成分组 `id=-2`。[素材库文档](https://doc.moyu.info/9280781m0.md)
- `POST /v1/assets/groups` 只返回带前缀的 `group_name`，不直接返回后续上传所需的数值 `id`；客户端创建后必须重新读取分组列表并定位该分组。[素材库文档](https://doc.moyu.info/9280781m0.md)
- 查询素材时，`group_id=-2` 只查历史素材；其他 `group_id<=0` 或不传会查当前令牌全部素材加历史素材；正数只查当前令牌可见的指定分组。[素材库文档](https://doc.moyu.info/9280781m0.md)

### “上传”实际上是 URL 导入

创建素材只接收单个公网可访问的 `url`，没有 multipart、文件字节、Base64、预签名上传或本地路径参数。因此用户主动导入素材库的本地文件必须先经过外部暂存。产品已决定使用火山引擎 TOS 作为这一中转层，具体安全架构见 [TOS 暂存上传设计](./tos-staging-design.md)；这不会改变 Moyu 素材接口本身仍只接受 URL 的事实。图片和视频生成结果不进入素材库，所以它们的本地保存不受这项限制。[素材库文档](https://doc.moyu.info/9280781m0.md)

`/v1/images/edits` 虽然接收 multipart 图片文件，但它是生成/编辑端点，不会创建素材记录，也不返回 `asset://`。它不能替代素材上传；素材节点作为编辑输入时需要先下载为字节，本地图片结果则可以直接读取文件字节。编辑输出的 Base64 直接保存成本地结果，不经 TOS 或素材库。[图片编辑文档](https://doc.moyu.info/497391425e0.md)

| 方式          | 请求                                       | 初始返回                | 后续查询                                      | 建议用途                                 | 来源                                             |
| ------------- | ------------------------------------------ | ----------------------- | --------------------------------------------- | ---------------------------------------- | ------------------------------------------------ |
| 同步 URL 导入 | `POST /v1/assets`，默认 `upload_mode=sync` | 真实 `id`、`asset_url`  | 以真实 ID 调用 `/v1/assets/get` 等待 `Active` | **桌面 MVP 默认**，可建立稳定素材身份    | [素材库文档](https://doc.moyu.info/9280781m0.md) |
| 异步 URL 导入 | `POST /v1/assets`，`upload_mode=async`     | 占位 `id`、`Processing` | 轮询 `/v1/assets/list` 取得真实素材记录       | 不希望长连接且能处理名称匹配歧义的调用方 | [素材库文档](https://doc.moyu.info/9280781m0.md) |

异步返回的占位 `id` 不能直接拼成 `asset://`，文档要求待列表出现 `Active` 记录后再读取真实 `asset_url`。由于文档没有提供占位 ID 与最终素材 ID 的稳定查询映射，桌面 MVP 使用同步模式。[素材库文档](https://doc.moyu.info/9280781m0.md)

### 真人（明星）素材 H5 授权

真人素材在普通 URL 导入前增加一次令牌隔离的人脸授权流程：[真人素材 H5 文档](https://kxzlbkdpvn.apifox.cn/9353151m0.md)

1. `POST /v1/assets/real-person/auth/link` 传 `artist_name`（最多 32 字符）和可选 `artist_desc`（最多 300 字符），取得仅 120 秒有效且只能使用一次的 `h5_url`。
2. 真人本人在手机 H5 页面完成刷脸后，客户端调用 `GET /v1/assets/real-person/groups` 查询已授权组。
3. 上传时必须把列表项的整数平台 `id` 作为 `POST /v1/assets` 的 `group_id`；不能误传展示用的上游 `group_id`（`group-xxx` 字符串）。该上传会触发同人脸校验，失败可能返回 `FaceMismatch`。
4. 单素材与整组永久删除分别使用 `POST /v1/assets/real-person/assets/delete` 和 `POST /v1/assets/real-person/groups/delete`。整组删除会同时删除组内全部素材。

实现中，普通素材继续自动解析“无限画布上传”分组；仅在暂存导入目标显式携带正整数 `groupId` 时跳过普通分组发现并进入真人素材组。所有 H5、查询、上传和删除操作均使用同一个 `providerConnectionId`，从而保持 API Key/Token 作用域一致。

### 素材状态归一化

| API 状态     | 内部状态     | 说明                       | 来源                                             |
| ------------ | ------------ | -------------------------- | ------------------------------------------------ |
| `Processing` | `processing` | 素材处理中                 | [素材库文档](https://doc.moyu.info/9280781m0.md) |
| `Active`     | `ready`      | 已审核并可用于视频生成     | [素材库文档](https://doc.moyu.info/9280781m0.md) |
| `Failed`     | `failed`     | 审核、下载、参数或超时失败 | [素材库文档](https://doc.moyu.info/9280781m0.md) |

`asset_url`（`asset://...`）应作为生成引用保存；`url` 是预览/下载地址。文档的列表和单素材响应把 `url` 描述为约 12 小时有效的签名 URL，过期后可重新查询刷新。[素材库文档](https://doc.moyu.info/9280781m0.md)

因此预览层必须以素材 ID为唯一恢复入口：不得把 `url` 写入画布持久化数据；已知到期时间时提前刷新，图片加载失败时以同一 ID强制重新查询。刷新失败只进入可重试的“预览暂时不可用”，不能把素材或画布连线标为损坏。自动刷新必须限制次数，并拒绝反复使用同一个失败 URL，避免过期地址导致无限请求。[素材库文档](https://doc.moyu.info/9280781m0.md)

## 生成结果保存

### 图片结果本地保存

文生图 HTTP 200 的 `data[]` 可以包含 URL 或 Base64；图片编辑 HTTP 200 的 `data[]` 只定义 Base64。对每个有效结果项分别执行以下流程：[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)

1. 文生图结果若存在 `url`，立即流式下载到同目录专用 `.part` 文件；文档没有说明 URL 有效期，因此不能把它当作长期预览源。[文生图文档](https://doc.moyu.info/495380766e0.md)
2. 文生图只有 `b64_json` 时，或处理任何图片编辑结果时，在 Tauri 后端把 Base64 解码到 `.part` 文件；这一过程不经过 TOS。
3. 通过文件魔数和可用 MIME 识别真实格式，校验非空内容并计算哈希；响应 `output_format` 只作候选扩展名。
4. 验证通过后原子改名为 `<Downloads>/无限画布/<safe(localGenerationTaskId)>-<resultIndex>.<实际扩展名>`；结果索引从 `1` 开始，单结果也使用 `-1`。
5. 创建本地图片结果记录和画布节点，不调用 `POST /v1/assets` 或其他素材接口。

只有文生图响应可能同时包含 `url` 和 `b64_json`；此时优先下载 URL，并保留完整原始响应用于诊断和必要的本地保存恢复。任何大段 Base64 都不得写入长期画布 JSON，但必须按任务原始返回保存策略完整留在任务调用记录中。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)

### 视频结果本地下载

视频生成成功响应会给出 `data.data.content.video_url`。素材库完整流程示例把它标为约 24 小时有效的签名 URL，因此应用不应等待用户手工保存，而应在任务成功后立即下载到本机。产品已决定视频结果不调用公司素材导入端点。[视频生成文档](https://doc.moyu.info/9280779m0.md) [素材库文档](https://doc.moyu.info/9280781m0.md)

建议的 MVP 流程：

1. 用提交任务时的同一 Bearer 令牌轮询到 `SUCCESS`，读取 `video_url`、模型、实际 `duration`、`resolution`、`ratio` 和用量快照。[视频生成文档](https://doc.moyu.info/9280779m0.md)
2. 通过操作系统路径 Interface 解析当前用户的 Downloads 目录，并定位“无限画布”目录；不能硬编码盘符、用户名、本地化目录名或供应商子目录。
3. 用远程 `task_id` 的文件系统安全形式作为文件名主体；扩展名以已验证的 MIME 或文件魔数为准，任务 `output_format` 只作候选。
4. 把 `video_url` 流式下载到同目录任务专用 `.part` 文件，结束后验证文件非空、基本媒体类型和可取得的内容长度，并计算内容哈希。
5. 验证通过后原子改名为最终文件，再把本地保存状态标为 `succeeded`。任务记录保存原始 `task_id`、最终路径、文件大小、MIME、内容哈希和保存时间。
6. 历史预览直接读取最终本地文件，不读取原始响应 URL。用户移动、改名或删除文件时标记 `local_missing`，但完整任务历史和原始响应继续保留。

任务列表中成功项的代理 URL 可用于诊断，但在明确其下载鉴权、Range 和有效期前，不作为规范下载源。自动下载优先使用单任务成功响应中的签名 `video_url`。[视频任务列表文档](https://doc.moyu.info/9280780m0.md) [视频生成文档](https://doc.moyu.info/9280779m0.md)

图片和视频本地保存消除了远程 URL 自然过期对历史预览的影响，但不能防止用户删除文件、下载目录被清理、磁盘损坏或本机数据丢失。本地结果以后要作为只接受公网 URL 的远程生成输入时，需要通过 TOS 按需取得公网 URL；该过程不创建公司素材记录。

### P2：会影响可靠性、成本或体验的未定义项

- 文生图和图片编辑都没有异步任务 ID、查询/恢复端点、回调、取消、幂等键、超时、限流或错误响应 Schema；连接中断后的请求无法可靠恢复或安全重试。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)
- 文生图文档没有定义 URL 有效期、Base64 图片格式、`created` 时间单位或 `usage` 对象字段；图片编辑虽定义 token usage，但也没有定义 Base64 编码格式、`created` 单位、价格或计费公式。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)
- `/v1/images/generations` 仍然只定义文生图字段，不接受参考图片；参考图片能力由独立 `/v1/images/edits` 提供，但没有遮罩、区域编辑或参考图角色字段。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)
- 视频生成没有取消端点、视频 Webhook、提交幂等键、重试语义或服务端并发/频率限制；产品已明确不提供取消，并自行对网络错误和 `5xx` 最多重试 3 次，但必须接受可能重复提交和计费的风险。批量请求仍不能按想象实现。[视频生成文档](https://doc.moyu.info/9280779m0.md)
- 视频生成没有价格、余额预检、用量计费公式或高分辨率成本协议；节点暂时不能显示可信的预计费用。[视频生成文档](https://doc.moyu.info/9280779m0.md)
- 任务列表在占位失败时可能返回空 `task_id`，又没有稳定任务记录 ID，跨重启去重不可靠。[任务列表文档](https://doc.moyu.info/9280780m0.md)
- 任务列表默认使用“服务器本地时区当天”，但文档没有说明服务器时区；客户端必须传明确 Unix 秒范围。[任务列表文档](https://doc.moyu.info/9280780m0.md)
- 五类响应封装不一致：文生图返回 `created/data/usage`，图片编辑返回更多必填输出元数据，视频提交返回 `task_id`，单视频任务和素材常用 `code: "success"`，任务列表使用 `success: true`。适配器不能依赖单一响应外壳。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md) [视频生成文档](https://doc.moyu.info/9280779m0.md) [任务列表文档](https://doc.moyu.info/9280780m0.md) [素材库文档](https://doc.moyu.info/9280781m0.md)
- 文生图结果 URL 完全没有 TTL 说明；图片编辑不返回 URL；视频结果 URL 的有效期只在素材库完整流程示例中标注约 24 小时，视频生成主文档也没有正式的刷新或重新签名协议。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md) [素材库文档](https://doc.moyu.info/9280781m0.md)
- `upload_mode=async` 只返回上游占位 ID，而文档要求通过素材列表寻找最终记录，没有定义占位 ID 到真实素材 ID 的稳定映射；同名并发上传存在关联歧义，因此桌面 MVP 使用同步模式。[素材库文档](https://doc.moyu.info/9280781m0.md)

## 建议的 MVP 适配器边界

```text
画布领域层
  ├─ PromptNode
  ├─ ImageAssetNode / VideoAssetNode / AudioAssetNode
  ├─ LocalImageResultNode / LocalVideoResultNode
  ├─ TextToImageNode
  ├─ ImageEditNode
  └─ VideoGenerationNode
           │
           ▼
ProviderConnectionRegistry(baseUrl, apiKeyRef, adapterId)
  ├─ ModelCatalog / ProviderModelBinding
  │
  ├─ GenerationProviderModule
  │    └─ createGenerationProvider(resolvedConnection)
  │              │
  │              ▼
  │    MoyuCompatibleGenerationAdapter
  │      ├─ buildTextToImageJsonRequest()
  │      ├─ submitTextToImageSynchronously()
  │      ├─ buildImageEditMultipartRequest()
  │      ├─ submitImageEditSynchronously()
  │      ├─ buildSeedanceRequest()
  │      ├─ submitVideoGeneration()
  │      ├─ pollVideoGeneration()
  │      └─ listVideoTasksForRecovery() ──────────────┐
  │
  ├─ LocalResultModule
  │    ├─ saveImageToDownloads(localTaskId, resultIndex, source)
  │    └─ saveVideoToDownloads(remoteTaskId, videoUrl)
  │
  └─ AssetLibraryModule
       └─ createAssetLibraryProvider(resolvedConnection)
                 │
                 ▼
       MoyuCompatibleAssetLibraryAdapter
         ├─ resolveAssetToFileBytesOrFreshUrl()
         ├─ list/createAssetGroups()
         ├─ importAssetFromPublicUrl()
         └─ pollAsset() ──────────────────────────────┤
                                                     ▼
                             当前供应商连接指向的 Moyu 兼容 API
```

同一 Moyu 兼容协议的多个供应商连接共用 `MoyuCompatibleGenerationAdapter`，连接之间只注入不同的 `baseUrl` 和 API Key 凭据。模型能力由共享模型定义保存，通过供应商模型绑定决定每个连接开放哪些模型；不能为同一模型复制供应商专用请求函数。素材库使用独立 Interface，但复用同一供应商连接解析机制。详细 Interface 见 [统一供应商模块设计](../provider-module-design.md)。

适配器可以派生最小的运行状态来驱动画布，但成功和失败接口都必须保存并返回未经改写的原始供应商响应，不能用归一化对象替代。每次生成要冻结提交时的操作类型、供应商连接、实际 Adapter、`baseUrl`、远程模型 ID、参数、端口角色、素材 ID、素材内容哈希、令牌凭据引用和请求快照；每次图片请求、视频提交和视频状态查询还要分别持久化 Adapter 实际发送的非敏感参数与完整原始返回。不能让画布后续编辑、任务终态或供应商配置修改已经保存的任务历史。两类图片请求还需要本地请求 ID 和结果索引，因为服务端都不返回图片任务 ID；视频任务则保存远程 `task_id` 与本地结果文件记录。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)

## MVP 契约测试清单

以下测试只验证文档声明的能力；其中涉及真实请求的部分需要公司提供测试 `BASE_URL` 和专用令牌。

1. 用令牌 A 创建分组、读取分组 ID，并确认令牌 B 无法读取该分组与素材。[素材库文档](https://doc.moyu.info/9280781m0.md)
2. 分别以 `Image`、`Video`、`Audio` 和单个公网 `url` 调用 `POST /v1/assets`，验证创建响应包含真实 `id/asset_url`、`/v1/assets/get` 最终进入 `Active/Failed`，并验证 `asset://` 可被同令牌生成任务引用。[素材库文档](https://doc.moyu.info/9280781m0.md)
3. 用公司确认的每个文生图模型显式提交 `model`、非空 `prompt`、默认与支持的 `size` / `quality`，验证未支持组合的真实错误行为。[文生图文档](https://doc.moyu.info/495380766e0.md)
4. 对文生图响应分别验证“仅 URL”“仅 Base64”“二者都有”“空 `data`”“结果项二者都无”；只把有效结果标为成功。[文生图文档](https://doc.moyu.info/495380766e0.md)
5. 用 `gpt-image-2`、一个 PNG 文件和非空提示词构造真实 multipart 请求，确认 Header、`image[]` part 名、文件名、MIME 和响应结构。[图片编辑文档](https://doc.moyu.info/497391425e0.md)
6. 分别以 0、1、2 和更多图片探测最小/最大数量，并验证调换图片顺序是否影响结果；以 PNG、JPEG、WebP 及超大文件探测格式、字节和像素限制，记录真实错误响应。产品已开放多图，测试结果用于提示和后端规则，不在前端复制硬限制。[图片编辑文档](https://doc.moyu.info/497391425e0.md)
7. 对图片编辑响应验证所有必填顶层元数据、三个必填 usage token、多个 Base64 结果、空 `data` 和缺失 `b64_json` 的处理。[图片编辑文档](https://doc.moyu.info/497391425e0.md)
8. 验证素材节点能通过刷新 URL下载为 multipart 文件输入；验证文生图 URL、两类图片 Base64 结果均不经过 TOS 或素材接口，而是保存为 `<Downloads>/无限画布/<safe(localGenerationTaskId)>-<resultIndex>.<实际扩展名>` 并创建本地图片结果节点。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md)
9. 对四个 Seedance 模型分别验证文生视频；对标准版再验证 1080p/4k，对 2.5 验证只开放 480p/720p 的保守策略。[视频生成文档](https://doc.moyu.info/9280779m0.md)
10. 验证首帧、首尾帧、参考图片、参考视频、参考音频各端口映射，并验证首尾帧与参考图片互斥。[视频生成文档](https://doc.moyu.info/9280779m0.md)
11. 验证 2.0 音频不能单独运行，2.5 可纯音频运行；验证各模型素材数量上限。[视频生成文档](https://doc.moyu.info/9280779m0.md)
12. 验证视频任务状态并集和 `progress`；模拟重启后用显式时间范围分页恢复任务，按 `SUCCESS` / `FAILURE` 拆分 `fail_reason` 双重语义。[任务列表文档](https://doc.moyu.info/9280780m0.md)
13. 验证视频成功后不调用 `POST /v1/assets`，而是把单任务响应的 `video_url` 下载为 `<Downloads>/无限画布/<safe(task_id)>.<实际扩展名>`；不创建供应商子目录，原始 URL 过期后历史仍使用本地文件播放。[视频生成文档](https://doc.moyu.info/9280779m0.md)
14. 验证文生图、图片编辑、视频任务和素材的不同成功外壳及所有非 2xx 都能被正确识别；失败时必须保存并展示收到的完整原始响应，不得生成替代错误信息。[文生图文档](https://doc.moyu.info/495380766e0.md) [图片编辑文档](https://doc.moyu.info/497391425e0.md) [视频生成文档](https://doc.moyu.info/9280779m0.md) [任务列表文档](https://doc.moyu.info/9280780m0.md) [素材库文档](https://doc.moyu.info/9280781m0.md)
15. 建立两个使用同一 Adapter、不同 `BASE_URL` 和专用令牌的供应商连接，共同绑定同一个模型；验证节点切换连接后只改变请求源地址和鉴权，模型、参数、请求体、图片顺序、视频顺序、音频顺序和原始错误展示保持一致。
16. 把令牌 A 的素材连接到令牌 B 的生成节点，验证应用不直接转发 A 的 `asset://`：图生图使用 A 下载的有序文件字节，视频生成使用 A 刷新的短期可读 URL，失败时保留连线并展示完整原始错误。
17. 使用供应商 A 和 B 分别生成图片，验证结果都由同一本地结果模块保存，命名只使用本地任务 ID 和结果索引；整个结果保存阶段不读取素材库凭据、不调用素材导入接口。
18. 同一节点连续启动多笔任务并从多个节点同时启动受控的大量任务，验证不存在应用并发上限或等待槽位；每笔任务快照、状态、错误和结果相互隔离，完成顺序不影响归属。
19. 图片同步请求在后台运行时继续操作画布；重启后，没有远程任务 ID 的未完成图片任务明确进入 `interrupted` 或 `unknown`，不自动重提。视频任务则使用冻结连接和 `task_id` 恢复。
20. 验证所有生成节点和任务面板均没有取消、停止或暂停动作；关闭面板、切换画布、删除节点不终止任务，删除节点后的图片和视频成功结果都继续保存到本地，但不重新创建原节点。
21. 分别模拟网络错误和 HTTP `500–599`，验证同一任务最多追加 3 次自动执行尝试、约 `2s/4s/8s` 退避、逐次提醒和完整原始错误历史；`4xx`、业务错误与解析错误不重试。
22. 视频取得 `task_id` 后模拟查询网络错误和 `5xx`，验证只重试查询而不重新提交生成；三次耗尽后停止自动轮询并进入查询降级状态。
23. 分别执行成功和失败的图片、视频任务，重启应用后验证所有任务仍存在，并能查看冻结参数、每次实际调用和未经改写的完整原始返回；删除来源节点或本地图片、视频结果文件也不能删除这些记录。
24. 验证每次调用记录包含实际 JSON 或表单字段、有序 multipart 文件元数据、HTTP 状态与响应头；请求凭据和签名参数被排除，但成功、失败以及包含 Base64 的响应体都不截断。
25. 中断图片或视频本地保存，验证 `.part` 文件不被当作可预览结果；恢复后只重新保存，不重新提交生成。模拟同名不同内容文件、磁盘空间不足和目录无权限，验证进入 `conflict` 或失败状态、不覆盖文件且完整保留本地保存错误。
26. 在提示词中分别引用两个同名但 ID 不同的素材，验证任务保存来源供应商连接、素材 ID、引用出现位置和实际内容哈希，不使用名称反查。
27. 把含 `@` 图片的提示提交给文生图，验证请求在本地编译阶段失败且未调用 `/v1/images/generations`；完整本地错误保留，芯片不降级为普通文字。
28. 把多张 `@` 图片提交给图片编辑，验证全部连接按稳定连线顺序成为 multipart `image[]`，渲染后的 `prompt` 使用 `图片 N` 且与文件 part 顺序一致；`@` 的出现顺序不改变位置或角色。
29. 把 `@` 图片、视频和音频提交给视频生成，验证 `metadata.content` 分别保持图片、视频、音频序列内的顺序和默认参考角色；首帧、尾帧、编辑和延长角色仍来自明确端口或任务设置。
30. 让素材签名 URL 过期后提交 `@` 引用，验证应用用稳定素材 ID 刷新地址并解析同一素材；刷新失败时展示完整素材接口返回，不搜索同名替代素材。
31. 引用本地生成结果后移动或修改文件，验证 `local_missing` 或内容哈希不一致会阻止请求，并展示完整本地解析错误；需要公网 URL 的视频请求只对通过校验的文件执行按需 TOS 中转。
32. 提示内容依次引用图片 A、视频 A、图片 B、音频 A，验证渲染提示、任务快照与实际请求中的位置分别为 `图片 1、视频 1、图片 2、音频 1`，不存在全局“素材 1–4”。
33. 并行刷新素材 URL、下载媒体和执行 TOS 中转，并故意让完成顺序与提示顺序相反；验证结果仍按冻结的 `(mediaType, typePosition)` 回填。
34. 让中间的 `图片 2` 解析失败，验证请求整体在供应商调用前失败，`图片 3` 不前移、不改号且没有部分请求发出。
35. 在网络错误或 `5xx` 后自动重试，验证三类媒体序列、每项同类型位置和内容哈希与首次尝试完全一致。

## 需要向公司接口方补充确认的最短问题清单

1. 文生图与图片编辑第一版分别允许哪些精确模型 ID？`gpt-image-1`、`gpt-image-2` 与说明中的 GPT-Image-2 是什么关系？

4. 图片编辑是通用“编辑/融合”还是图生图？是否支持遮罩、编辑区域或图片角色？同类型输入顺序已作为公司补充契约确认，不再列为待确认项。

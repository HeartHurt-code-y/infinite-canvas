# 异步生成任务设计

状态：MVP 设计 v0.8

## 产品含义

图片生成节点的纯文字或图片参考操作，以及视频生成节点的生成操作，都以异步生成任务运行。用户触发生成后，画布只等待本地任务记录成功持久化，随后立即得到任务 ID，可以继续编辑画布或启动更多任务；视频任务固定由节点头部的向右播放图标触发。远程请求和结果处理在 Tauri 后台独立进行。生成任务无论成功、失败、结果未知还是被进程中断，都继续作为可查询的持久记录保存。

“无限并发”采用以下精确定义：

- 产品业务层没有并发数量配置、信号量、工作槽位或本地等待队列。
- 同一节点和不同节点都可以同时启动任意数量任务。
- 每笔任务创建后立即尝试执行，不等待其他生成任务结束。
- 无限不是物理承诺。操作系统、HTTP 连接池、设备内存、公司后端、供应商限流、余额和配额仍可能拒绝或延迟请求。
- 真实约束产生的错误归属于对应任务，并完整展示原始错误；应用不伪造一个“超过本地并发上限”的错误。

## 任务关系

```text
生成节点 ──每次触发──> 本地生成任务 ──后台执行──> 供应商请求
                              │
                              ├─ 同步图片响应 ─> 生成结果
                              │
                              └─ 远程视频任务 ─> 轮询 ─> 生成结果

本地生成任务 ──图片成功──> 本地保存记录 ─> Downloads 中的本地图片结果
             └─视频成功──> 本地保存记录 ─> Downloads 中的本地视频结果
```

- 一个生成节点可以拥有任意多个本地生成任务。
- 一次触发只创建一个本地生成任务；生成数量仍由单次请求契约决定。视频节点头部播放图标每点击一次就是一次独立触发。
- 一个本地生成任务包含一次初始执行尝试；遇到符合条件的网络错误或 HTTP `500–599` 时，最多追加 3 次自动执行尝试，但任务 ID 和冻结快照不变。
- 一个本地生成任务只代表一次用户发起的业务生成；该业务生成最多包含 1 次初始尝试和 3 次自动重试，但图片任一成功响应仍可以包含多个结果项。
- 只有供应商返回任务 ID 的操作才具有远程生成任务；当前视频有，图片没有。
- 图片和视频结果的本地保存是独立阶段，不占用或释放所谓的“生成并发槽位”，因为产品没有这种槽位。

## 状态模型

| 本地状态      | 含义                                                                 |
| ------------- | -------------------------------------------------------------------- |
| `created`     | 任务 ID 和快照已持久化，后台执行即将开始                             |
| `submitting`  | 正在解析素材、构造请求或等待同步提交响应                             |
| `retry_wait`  | 提交阶段符合自动重试条件，正在等待下一次指数退避执行尝试             |
| `queued`      | 供应商已接受远程任务并报告排队；不是本地并发队列                     |
| `running`     | 供应商报告正在生成，或远程任务正在执行                               |
| `succeeded`   | 供应商已明确报告生成成功并返回至少一个有效结果                       |
| `failed`      | 收到明确失败、非 2xx、协议错误或本地执行错误                         |
| `unknown`     | 请求可能已到达供应商，但无法确认最终结果                             |
| `interrupted` | 应用退出或进程中断了不可恢复的本地同步请求，且没有远程任务 ID 可查询 |

生成状态与结果保存状态分开。图片或视频生成 `succeeded` 后，每个结果的本地保存可处于 `pending`、`writing`、`succeeded`、`failed`、`interrupted`、`local_missing` 或 `conflict`。任何保存失败都不能回写为生成失败。

供应商返回有效媒体后，任务先发出 `generation:result-ready`，前端可使用事件中的会话内预览地址立即展示结果；下载、校验和本地文件落盘继续在后台执行。保存完成后再发出 `generation:result-saved`，前端将预览地址替换为稳定的本地 `finalPath`。预览地址不写入画布文档，也不作为重启后的结果引用。

进入任何终态都只更新任务当前状态，不能删除任务、请求快照、执行尝试、返回信息、状态事件或结果保存记录。

### Lifecycle persistence module

生成任务持久化由 `GenerationTaskLifecycle` 这个 deep internal module 管理。它的 mutation
interface 是 `create(task)`、`commit(taskId, typedFact)` 与启动恢复；调用方不再直接写任务行、
执行尝试、provider call、结果行或任意字符串事件。原状态图仍存在，但已降为 module
implementation 的私有 journal 规则，不再构成可被调用方绕过的 shallow seam。

typed fact 覆盖解析、提交、远端观察、文本生成、provider call、结果保存和恢复。implementation
按一个事实所表达的因果关系在单个 SQLite transaction 中统一负责：

- `BeginResolution` 同时完成 `created → submitting` 和 resolve attempt 创建；解析成功同时结束 attempt 并冻结不可覆盖的 resolved request。
- submit 与 observe attempt number 由 journal 分配，调用方不能扫描历史后自行加一。
- provider call 必须按 prepared、sent、responded/failed 顺序记录；成功提交、成功观察和文本成功必须引用同一 task/attempt 下已归档的 2xx `callId`。
- 同步图片成功同时结束 submit attempt、写 token、进入 `succeeded`、登记全部 `pending` 结果并追加状态事件。
- 视频提交成功同时结束 submit attempt、写 token、绑定不可换绑的远程任务 ID、进入 `queued` 并追加状态事件。
- 每次远端观察同时结束 observe attempt、写 token、更新 query health/status/progress；成功视频还会在同一 commit 中登记 `pending` 结果。
- 提交或查询重试同时结束失败 attempt、更新 task/query health 并追加规范化 retry event；没有完成的 provider call 证据时拒绝重试。
- 本地保存状态只通过 `ResultChanged` 写入并追加 `result_save_changed`；它与生成状态正交，保存失败不能改写生成终态。
- 验证合法状态图；终态不可离开，远端 ID 非空且不能换绑，`running` 不因迟到的 `queued` 回退，progress 单调且位于 `0–100`。
- 任一步验证或 SQL 失败都会回滚整个 fact，包括已经执行的 attempt 结束、token 或结果插入。

任务创建在一个 transaction 内写入冻结快照与 `created` 事件。SQLite commit 是事实来源；
Tauri 实时事件和通知只消费 commit receipt，发送失败不回滚持久记录。SQLite 与文件都是
local-substitutable 依赖：interface 测试使用临时 SQLite 文件和真实 transaction，不增加只有
一个 implementation 的抽象 port；provider 则是 true external adapter。

SQLite 与文件系统不能共享 transaction，因此结果落盘使用可恢复顺序：先登记 `pending`，再写
`writing`，写 `.part`、校验并原子 rename，最后提交 `succeeded`。启动恢复会在同一 transaction
把遗留的 `pending/writing` 改为 `interrupted` 并追加事件，然后只恢复本地保存，不重新提交生成。

## Task Module Interface

画布不直接等待供应商 Adapter。外部 seam 由 Task Module 提供：

```ts
interface GenerationTaskModule {
  start(command: StartGenerationCommand): Promise<GenerationTaskId>;
  recover(): Promise<GenerationRecoveryReport>;
  list(query: GenerationTaskListQuery): Promise<GenerationTaskPage>;
  get(taskId: GenerationTaskId): Promise<GenerationTaskDetail>;
}
```

`start` 的 Promise 只覆盖本地校验、任务 ID 分配和任务快照持久化，不覆盖远程生成。成功返回后，Task Module 在后台调用统一供应商模块，并把状态事件写入任务存储。

`recover` 只恢复具有可靠远程身份的任务。当前视频任务可以使用冻结的供应商连接和远程 `task_id` 恢复；未返回结果的同步图片请求不能恢复为同一远程任务。

`list` 返回适合分页或虚拟化展示的轻量任务摘要；`get` 返回单个任务的冻结请求、全部执行尝试、返回信息、状态事件、结果和保存状态。任务列表、节点徽标和详情面板通过这两个查询读取持久存储，不各自直接管理网络 Promise。这样一个任务的界面卸载、节点离开视口或画布切换不会取消或丢失其他任务。

Interface 刻意不包含 `cancel`、`stop` 或 `pause`。这不是暂缓实现的占位能力，而是 MVP 明确不支持的业务操作。

## 任务快照与调用记录

每次 `start` 必须先持久化逻辑请求快照：

- 本地任务 ID、来源节点 ID 和创建时间。
- 操作类型、供应商连接、Adapter、`baseUrl`、API Key 凭据引用和远程模型 ID。
- 由生成节点内文字片段和 `@` 媒体引用组成的结构化提示内容，以及每个引用的目标素材节点实例 ID、来源身份、出现位置和显示名称快照。
- 生成数量和全部模型参数。
- 每条输入连线的稳定 `edgeOrder`，以及每个媒体输入的目标画布节点 ID、来源供应商连接、素材或本地结果身份、媒体类型、同类型位置、角色和提交时内容标识。
- 统一的 Downloads 保存策略；图片使用本地任务 ID 和结果索引计算文件名，视频在远程 `task_id` 返回后追加最终文件名与路径。
- 用户提交的全部非敏感参数及其显式值、默认值来源和参数顺序。
- 后续每次供应商调用的实际非敏感请求、完整原始返回或原始运行时异常。
- 每次执行尝试的编号、阶段、开始和结束时间、实际退避时长以及调用结果。

API Key 明文、Cookie、TOS 签名查询串和临时素材预览 URL 不进入任务快照。媒体引用保存稳定身份；本地绝对路径只进入本地结果解析记录，不替代引用身份。

逻辑请求快照用于回答“用户触发生成时提交了什么”；每次调用记录用于回答“Adapter 最终向哪个端点实际发送了什么、供应商实际返回了什么”。Adapter 注入的默认值、字段映射或图片、视频、音频各自的输入顺序必须出现在实际调用记录中，不能只保存节点表单。

## 结构化提示与媒体引用解析

图片和视频生成节点从自身提示词输入框向 Task Module 提交结构化提示内容，而不是提前拼接好的字符串。`start` 先持久化文字片段、每个 `@` 引用的目标素材节点实例 ID，以及当前节点的全部输入连线，随后后台解析并形成一次任务专属的有效输入列表。

```ts
interface MediaReferenceModule {
  resolve(command: ResolvePromptReferencesCommand): Promise<ResolvedPromptBundle>;
}
```

这个 Interface 只暴露一次解析操作；公司素材查询、跨供应商凭据选择、本地结果读取、签名 URL 刷新、TOS 按需中转、内容哈希、排序和不同生成操作的字段映射都隐藏在 Module Implementation 内。

### 解析时序

1. Task Module 持久化本地任务 ID、生成节点内结构化提示和全部输入连线；每条连线使用创建时分配、节点范围内稳定的 `edgeOrder`，不能依赖数组读取或画布位置临时推断。
2. Media Reference Module 校验每个 `@` 芯片的 `canvasNodeKey` 仍指向当前生成节点的一条输入连线。断线或已删除目标必须解析失败，不能按名称或来源素材 ID 寻找替代实例。
3. Module 按全部连接的 `edgeOrder` 冻结完整媒体计划（身份、位置与显式角色）；同一 `canvasNodeKey` 的多次引用只解析一次，三种媒体分别从 `1` 连续编号。提示引用查同一计划，不改变位置或角色。带位置的请求在读取媒体前校验同类型位置与全局顺序一致；无位置历史请求保留原排序。
4. Module 校验媒体仍可读取。本地文件必须与已有保存记录的内容哈希一致；公司素材有版本或内容标识时也必须一致。来源接口没有版本契约时，任务明确记录“提交时下载并冻结的内容哈希”，不能假装能证明选择时到提交时从未变化。
5. Module 形成 `images[]`、`videos[]`、`audios[]` 三个有效输入列表。相同来源素材通过不同画布实例连入时分别保留；只有相同 `canvasNodeKey` 因多个芯片或必要连线产生的重复计数被合并为一个位置。
6. 根据操作类型编译：图片生成节点的纯文字操作拒绝所有媒体输入；图片参考操作只接受 `images[]` 并按图片位置生成有序 multipart；视频生成把三类媒体引用映射为默认参考角色，特殊角色继续来自明确输入且仍占据所属类型位置。
7. 在任何供应商请求发送前，持久化解析后的目标节点实例 ID、来源身份、媒体类型、提示出现位置、同类型位置、字节数、MIME、内容哈希、最终角色、三类有效顺序和渲染后的实际提示字符串。
8. Provider Adapter 再把已解析 bundle 映射为实际请求，并通过统一调用捕获路径记录最终非敏感参数。

解析失败属于任务的原始本地执行错误：任务进入 `failed`，不创建供应商调用记录，也不发送可能计费的请求。详情完整保存并展示错误类型、消息、堆栈、cause 链、引用身份和失败阶段；不能替换为笼统文案、删除芯片或寻找同名素材替代。

### 分类型顺序不变量

公司已确认模型按照素材传入顺序识别位置，并且图片、视频和音频分别维护独立顺序。这条契约由 Media Reference Module 统一保证，调用方和 Adapter 不得重新解释。

- 一个输入出现使用 `(mediaType, typePosition)` 定位，例如 `(image, 2)`、`(video, 1)`；不存在跨类型全局素材位置。
- 提示内容依次出现“图片 A、视频 A、图片 B、音频 A”时，位置必须是 `图片1、视频1、图片2、音频1`。
- 同一 `canvasNodeKey` 被一个或多个芯片引用时只占一个输入位置；同一来源素材的不同画布实例具有不同 `canvasNodeKey`，因此可以分别占位。
- 媒体解析允许并行，但每个 Promise 结果必须写回预先冻结的同类型位置；不能按照下载、刷新或 TOS 上传完成顺序组装请求。
- Adapter 必须按图片位置构造 `image[]`，并在混合媒体请求中分别保持图片、视频、音频内部顺序；不得按角色、文件名、ID、大小或来源供应商排序。
- 某个位置解析失败时整笔请求失败，不删除失败项、不压缩后续位置、不发送部分请求。
- 自动重试复用三类冻结序列和内容哈希，不重新解析提示词位置；只有用户显式重试创建的新任务才重新冻结当前输入。

### 精确性的边界

- “精确引用”保证芯片指向哪个已连线画布素材实例、该实例来自哪个稳定对象、实际解析到哪份字节，以及同类型媒体位置和请求映射可审计。
- 显示名称、素材分组、预览 URL 和本地路径都不是身份；素材改名不改变引用。
- 任务提交后修改提示词、删除芯片、移动节点或重命名素材，不改变已冻结任务。
- Adapter 生成 `[图片1：名称]`、`[视频1：名称]`、`[音频1：名称]` 等确定性文本标记，并确保它们分别对应实际图片、视频、音频输入的同类型位置；不能生成跨类型的 `[素材 N]`。位置映射是已确认的接口契约，但不能保证模型输出一定遵守创作意图。
- 每个生成节点独立保存自己的结构化提示；一个节点的提示编辑或不兼容失败不能修改其他生成节点的提示或任务。

### 持久化不变量

1. `start` 只有在任务 ID 和完整逻辑请求快照成功写入持久存储后才能返回；持久化失败时不得启动远程请求。
2. 每次供应商调用都必须先写入带 `callId`、`attemptId` 和调用阶段的请求记录，再发送 HTTP 请求。进程在发送后中断时，该记录明确显示“已发送但未取得返回”，不能伪造响应。
3. HTTP 返回或运行时异常到达后立即追加到同一调用记录；成功 lifecycle fact 必须引用同一 task/attempt 下已经完成的 2xx `callId`，不能用没有调用证据的状态 setter 伪造成功。
4. 同步图片的 `succeeded` 与全部 `pending` 结果、视频提交的远端身份与 `queued`、视频成功观察与 `pending` 视频结果分别在一个 transaction 提交；任务摘要、attempt、token、结果和事件不能分步写入。
5. 状态更新只改变任务摘要的当前投影；调用记录、状态事件和以前的响应采用追加方式保存，后续成功、失败、重试或恢复都不能覆盖旧记录。
6. `succeeded`、`failed`、`unknown`、`interrupted` 以及视频查询 `degraded` 都不是清理信号。MVP 不设置任务 TTL、最大历史条数、终态垃圾回收、单条任务删除或“清空历史”。
7. 删除来源节点、关闭任务面板、切换画布、重启应用、修改供应商配置，或移动、改名、删除本地图片和视频结果，都不能删除生成任务历史。只有未来明确设计的整个画布或项目数据删除操作才可以连同其任务记录一起处理。
8. 供应商返回的临时结果 URL 即使后来过期，其原始字符串仍保留在返回记录中；图片和视频历史预览都使用已经校验并保存的本地文件。

本地存储介质损坏或空间耗尽时无法物理保证写入。此类持久化错误必须完整展示，且在请求记录成功落盘前禁止发送远程请求，避免产生一笔没有本地审计记录的生成或计费。

### 每次调用保存的请求与返回

任务详情按执行顺序展示每个生成提交和视频状态查询调用：

| 区域       | 必须持久化并展示的内容                                                                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 任务摘要   | 任务 ID、来源节点、创建和结束时间、当前状态、供应商连接、模型、远程任务 ID、结果及保存状态                                                                                                           |
| 逻辑请求   | 结构化提示、`@` 目标画布节点 ID 与提示位置、输入连线 `edgeOrder`、生成数量、全部模型参数、图片/视频/音频各自的同类型位置、角色、来源身份、内容标识、统一的本地保存目标，以及显式值和默认值           |
| 实际请求   | 调用阶段、HTTP 方法、去除凭据后的最终地址、非敏感请求头、Body 类型、渲染后的提示字符串、实际 JSON 或表单字段；媒体项显示类型位置，multipart 文件显示图片位置、字段名、文件名、MIME、字节数和内容哈希 |
| HTTP 返回  | 到达时间、耗时、状态码、状态文本、全部响应头以及未经截断、摘要、改写的原始响应文本或字节                                                                                                             |
| 运行时异常 | 没有 HTTP 返回时的原始异常类型、消息、堆栈和完整 cause 链                                                                                                                                            |
| 解释结果   | Adapter 派生的任务状态、远程任务 ID、进度、结果索引和图片或视频本地文件记录；它只能作为原始返回的附加视图                                                                                            |

- JSON 请求保存 Adapter 映射完成后的实际字段和值；multipart 不重复持久化大型媒体字节，而是保存可验证的稳定素材引用和内容哈希。
- `Authorization`、API Key、Cookie、TOS 签名查询参数及其他请求凭据既不保存也不展示；对应字段显示“已排除敏感凭据”，不能显示假值冒充原值。
- 安全排除只作用于请求凭据。供应商返回的成功和失败响应都完整保存；不能因为响应很大、包含 Base64 或任务已经成功而截断或只保存解析结果。
- 视频生成保存提交返回，并保存后续每一次状态查询的请求和原始返回。自动重试产生的调用按 `attemptNumber` 独立排列。
- 详情默认可展示格式化 JSON，但必须同时提供原始视图、复制和导出；大响应延迟加载或虚拟化显示，不得截断持久化内容。

## 不设并发上限的执行规则

1. 每次触发都分配新的任务 ID，不复用节点上的 `activeTaskId`；视频节点头部播放图标每次点击都属于独立触发。
2. 任务持久化成功后立即启动独立后台执行，不检查全局或单节点运行数量。
3. 执行入口不因任何已有任务的 `submitting`、`queued`、`running` 或结果保存状态而禁用；视频节点头部播放图标同样保持可用。
4. 不实现 `maxConcurrentTasks`、`pendingSlotQueue`、每供应商 semaphore 或“等待第 N 个任务完成”的逻辑。
5. HTTP 客户端和操作系统可以因物理资源自行调度连接；应用不能把这种传输行为描述为产品并发限制。
6. 任务状态只按任务 ID 更新，禁止节点级单例 `status/result/error` 被多任务竞争覆盖。
7. 多任务可以任意顺序完成。输出按任务 ID 和结果索引保存，展示顺序与完成顺序是两个独立维度。
8. 一个任务失败不取消、暂停或改写同节点和其他节点的任务。
9. 供应商 `429`、配额、余额、内容审核或资源错误不触发全局熔断，也不自动降低用户后续任务的并发。
10. 网络错误和 HTTP `500–599` 按固定策略自动重试；其他错误不自动重试。用户在自动重试耗尽后显式重试，会复制原快照形成新任务 ID，并清楚显示它是一笔新的可能计费请求。

## 网络错误与 5xx 自动重试

自动重试只应用于生成供应商调用，包括图片节点的纯文字提交、图片参考提交、视频生成提交和视频任务状态查询。图片或视频结果的本地保存与 TOS 暂存继续使用各自阶段的重试规则，不计入生成执行尝试。

### 次数与退避

- 第 1 次是初始执行尝试，不计入“重试 3 次”。
- 初始尝试失败后最多自动重试 3 次，因此同一生成任务最多有 4 次执行尝试。
- 第 1、2、3 次自动重试的名义等待时间分别为 `2s`、`4s`、`8s`。
- 实际等待时间为 `2000ms × 2^(retryIndex-1)`，再增加 `0%–20%` 随机抖动，避免无限并发任务在同一时刻重发。
- 重试等待不会占用本地并发槽位，因为产品没有并发槽位；其他任务继续独立启动和运行。
- 任务在 `retry_wait` 时仍不支持取消、停止或暂停。

### 可重试错误

- 没有 HTTP 响应的网络或传输错误：DNS、TLS、连接建立失败、连接重置、连接意外关闭和超时。
- HTTP 状态码 `500–599`，无论响应体是否为 JSON。

以下错误不自动重试：

- HTTP `400–499`，包括 `408` 和 `429`。
- 参数、模型、素材、权限、审核、余额、配额和业务规则错误。
- HTTP 成功但响应 JSON、Base64 或结果字段无法解析的协议错误。
- 用户显式重试产生的新任务，以及生成结果本地保存和 TOS 暂存阶段的错误。

### 尝试归属与原始错误

- 自动重试不创建新生成任务；所有执行尝试使用同一个任务 ID 和完全相同的冻结快照。
- 自动重试必须复用完全相同的 `images[]`、`videos[]`、`audios[]` 位置与内容哈希；并行解析或重试完成顺序不能改变任何同类型位置。
- 每次执行尝试分配独立的 `attemptId` 和从 `1` 开始的 `attemptNumber`。
- 每次请求参数、网络异常、状态码、状态文本、响应头和未经改写的原始响应体全部永久保留在该任务的尝试历史中。
- 后续尝试成功不能删除或覆盖前面尝试的错误。错误面板默认展示最终尝试，并允许逐次展开、复制和导出全部原始记录。
- 自动重试通知是额外的任务状态消息，不能代替、摘要或改写原始错误。

### 用户提醒

每次进入 `retry_wait` 都写入任务事件并发出非阻塞提醒，至少包含：

- 任务和来源节点。
- 当前是第几次自动重试，例如 `1/3`。
- 实际倒计时。
- 触发原因类别，例如“网络错误”或 `HTTP 503`。
- “请求可能已被供应商接收，自动重试可能造成重复生成或重复计费”的固定风险提醒。

提醒中不拼接 API Key、签名 URL 或请求凭据。用户点击提醒后打开该执行尝试的完整原始错误。多个任务同时重试时，界面可以聚合弹出的提醒数量，但每个任务的事件历史必须分别完整保留。

第 3 次自动重试仍失败时，发出“自动重试已耗尽”的提醒，不再安排第 4 次重试。最终状态按最后一次错误确定：明确 HTTP `5xx` 为 `failed`；始终没有可靠 HTTP 响应且无法确认供应商是否执行时为 `unknown`。

### 视频提交与轮询

- 视频提交尚未取得远程 `task_id` 时，网络错误或 `5xx` 会重新发送同一提交请求，最多 3 次。当前接口没有幂等键，因此可能产生多个远程任务或重复计费；每次提醒都必须明确此风险。
- 一旦已经取得远程 `task_id`，后续状态查询的网络错误或 `5xx` 只重试查询请求，绝不能重新提交生成。
- 查询重试期间保留最近一次已知的 `queued` 或 `running` 生成状态，并单独显示查询健康状态 `retry_wait`；不能把短暂查询错误改成远程生成失败。
- 同一轮状态查询连续 3 次自动重试仍失败后，标记查询健康状态为 `degraded` 并提醒用户，停止该任务的自动轮询；用户可以显式“重新查询状态”，但这不会创建新的生成任务或重新提交生成。

## 不支持取消、停止或暂停

生成任务一旦成功创建，就只能通过执行过程自然进入 `succeeded`、`failed`、`unknown` 或 `interrupted` 等终态。产品不提供用户发起的取消、停止或暂停操作。

以下行为都不能取消生成任务：

- 关闭任务详情或任务面板。
- 节点离开当前视口。
- 切换到其他画布。
- 修改节点的供应商、模型、提示词、参数或连线。
- 删除、替换或重新排序提示词中的 `@` 媒体引用。
- 删除生成节点。
- 删除或断开原输入连线。
- 另一笔任务失败、限流或余额不足。
- 图片或视频结果本地保存失败。

Task Module、Provider Adapter 和前端动作定义中都不增加 `cancelTask`、`stopGeneration`、`pauseTask` 或用户可触发的 AbortSignal。即使未来某个供应商提供取消端点，MVP 也不调用，除非产品规则以后明确修改。

删除仍有任务运行的生成节点时：

- 已持久化任务使用冻结快照继续执行。
- 图片和视频成功结果仍按冻结的保存策略写入解析后的 Downloads 目标。
- 已删除的生成节点不会因任务完成而被自动重新创建。
- 图片和视频结果都保留在任务历史和本地文件中，不自动进入公司素材库。

关闭整个桌面应用是进程生命周期事件，不是产品取消操作。远程视频任务会继续在供应商运行并在重启后恢复轮询；本地正在等待的同步图片请求可能进入 `interrupted` 或 `unknown`，不能标记成 `cancelled`。

TOS 暂存上传也不提供取消、停止或暂停。用户只能在暂存流程开始前从待上传列表移除文件；流程开始后关闭面板或切换画布不能终止它，运行中记录不能删除。应用退出导致上传中断时记录 `interrupted`，不能标记成 `cancelled`。

## 同步图片接口的异步包装

文生图和图生图供应商端点仍是同步 HTTP。Task Module 通过后台执行让画布非阻塞，但不能改变上游契约：

- `submitting` 期间后台连接仍在等待完整 HTTP 响应。
- 用户关闭任务面板或切换画布不停止该请求。
- 关闭整个应用会终止桌面端正在等待的连接；供应商是否仍完成请求不可知。
- 重启后，未得到明确响应且没有远程任务 ID 的任务标记为 `interrupted` 或 `unknown`。
- 只有网络错误和 HTTP `500–599` 按上述固定策略自动重提，最多 3 次；每次都提示可能重复生成和重复计费。其他错误和应用重启后不自动重新提交。

如果以后要求图片任务在桌面应用退出后继续运行并可靠恢复，需要公司后端增加持久化任务执行层，至少提供提交任务、任务 ID、状态查询、原始响应保存和幂等协议；或者由图片供应商提供等价能力。

## 生成结果本地保存

图片同步响应取得有效 `data[]` 结果，或视频任务轮询到 `SUCCESS` 并取得 `content.video_url` 后，都不调用公司素材导入端点。Task Module 为每个结果创建独立本地保存记录，由 Tauri 后端立即写入操作系统 Downloads 目录。

### 路径与命名

| 结果类型 | 最终路径                                                             |
| -------- | -------------------------------------------------------------------- |
| 图片     | `<Downloads>/无限画布/<safe(localTaskId)>-<resultIndex>.<extension>` |
| 视频     | `<Downloads>/无限画布/<safe(remoteTaskId)>.<extension>`              |

- `<Downloads>` 必须通过操作系统路径 Interface 解析，不能硬编码用户名、盘符或语言相关目录名。
- 图片接口没有远程任务 ID，文件名使用本地生成任务 ID 和从 `1` 开始的结果索引；即使只有一个结果也保留 `-1`。
- 视频文件名主体直接使用供应商视频接口返回的远程 `task_id`；本地生成任务 ID 继续作为数据库主键，两者不能混用。
- 图片和视频都直接保存在同一个“无限画布”目录，不按供应商连接创建子目录，也不在文件名中增加供应商标识。
- 文件系统非法字符需要确定性安全转换，同时在保存记录中保留未经改写的本地任务 ID、结果索引、远程 `task_id` 和最终路径。
- 扩展名依次根据响应文件魔数或 MIME、响应元数据、受控默认值决定；禁止仅从可能带签名参数的 URL 后缀猜测。

### 原子保存与状态

1. 在最终目录创建同任务、同结果索引专用的 `.part` 临时文件，不直接写最终文件。
2. 图片 URL 和视频 URL 流式下载到临时文件；Base64 图片在 Tauri 后端解码到临时文件。结果保存过程不进入公司素材库或 TOS。
3. 写入结束后验证文件非空、基本媒体类型和可获得的内容长度，计算内容哈希。
4. 验证通过后原子重命名为最终文件，再把本地保存状态提交为 `succeeded`。
5. 最终记录保存本地任务 ID、结果索引、原始远程 `task_id`（如有）、最终绝对路径、相对目录、字节数、MIME、内容哈希和完成时间。

本地保存状态使用 `pending`、`writing`、`succeeded`、`failed`、`interrupted`、`local_missing` 和 `conflict`。图片或视频远程生成 `succeeded` 后，本地保存失败不能把生成状态改为失败。

- 目标文件已存在且保存记录中的大小和内容哈希一致时直接复用，不重复覆盖。
- 目标文件已存在但内容不同或无法证明属于同一结果时进入 `conflict`，停止保存并展示完整冲突信息，不能静默覆盖、添加供应商后缀或自动改名。
- 磁盘空间不足、目录无权限、下载断开、Base64 解码失败、校验失败和原子改名失败都保存并展示完整原始错误。
- URL 下载的网络错误或 HTTP `500–599` 在本地保存阶段使用独立的 `2s/4s/8s` 指数退避与少量抖动，最多自动重试 3 次并逐次提醒；它只重试结果下载，不重新提交或重跑远程生成。Base64 解码、磁盘写入和格式校验错误不按网络规则自动重试。
- 下载得到 `401` 或 `403` 时先用冻结连接和远程 `task_id` 重新查询任务以尝试取得新的 `video_url`，然后继续剩余下载重试；其他明确 `4xx` 不自动重试。
- 应用退出导致保存中断时，本地保存记录进入 `interrupted`，最终文件不能标为可预览；图片可以从持久化的完整 Base64 原始响应重新解码，URL 结果仍需可取得有效地址，所有恢复都只重试保存，不能重新提交生成。
- 本地保存开始后不提供取消、停止或暂停。关闭面板、切换画布或删除来源节点不能中止保存；退出应用属于进程中断，不记录为用户取消。
- 历史预览在 `succeeded` 时直接读取本地文件，不读取历史响应 URL。文件被用户移动、改名或删除时标记 `local_missing`，保留任务、原始响应和路径记录。
- 应用不自动删除已完成图片或视频，也不以磁盘空间为由清理旧结果。磁盘损坏、用户删除、系统清理或设备丢失不属于 URL 过期，MVP 不承诺从这些情况恢复。

本地图片结果可以直接作为图生图 multipart 文件字节；当图片或视频结果要作为只接受公网 URL 的远程生成输入时，需要另行通过 TOS 取得供应商可读取的短期 URL。该按需中转不创建公司素材记录，也不改变本地文件作为生成结果主副本的身份。

## 视频任务轮询

- 每个视频任务使用提交时冻结的供应商连接和远程 `task_id`，不读取节点当前选择。
- 新任务并发启动不受轮询数量影响。
- 正常轮询按供应商要求和任务阶段调度；单次查询遇到网络错误或 HTTP `500–599` 时使用固定的 `2s/4s/8s` 指数退避与抖动，最多自动重试 3 次。
- 退避只减少状态查询频率，不建立生成提交队列，也不限制用户继续生成。
- 每次轮询尝试保留完整原始错误；短暂查询失败不能擅自把远程生成任务标为失败。
- 连续 3 次查询重试耗尽后停止该任务的自动轮询并标记查询健康状态 `degraded`；用户可手动重新查询状态，不能重新提交生成。
- 应用重启后只恢复非终态且具有远程任务 ID 的任务；已完成任务直接读取本地快照，需要时再刷新结果地址。

## 大量任务的界面规则

- 节点只显示轻量汇总，例如运行数量、成功数量和失败数量，不在节点内部渲染全部任务详情。
- 任务面板使用分页、增量读取或虚拟化列表，不能随着任务总数线性创建常驻媒体播放器和预览请求。
- 成功、失败、未知和中断任务全部出现在历史列表中；不能默认隐藏失败记录，也不能只保存最近一次任务。
- 单个任务展开时显示只读的“请求参数”“调用与返回”“结果与保存”区域；每个执行尝试和视频查询都可以查看自己的实际请求和原始返回。
- 单个任务展开时才加载完整响应、结果预览和诊断内容；成功响应和原始错误都不截断。
- 画布卸载某个节点的视觉元素不能删除任务记录或停止后台执行。
- 多个任务同时完成时，逐笔写入结果，不能用“最后一次完成”覆盖节点以前的任务历史。

## MVP 验收测试

1. 同一节点连续触发 20 次，每次立即返回不同任务 ID，没有本地等待槽位或执行入口锁定；视频节点通过头部向右播放图标触发时同样成立。
2. 多个节点同时启动受控的大量任务，验证代码中不存在硬编码并发上限，任务数量超过测试样本后不会被产品规则拒绝。
3. 人为让第 1 笔任务最后完成，验证它不会覆盖第 2～20 笔任务的状态、错误或结果。
4. 让其中一笔返回 `429`、一笔返回非 JSON `400`、一笔成功；验证前两笔不自动重试、三笔互不影响且失败任务显示完整原始响应。
5. 同一节点运行期间继续修改提示词、模型和连线，验证已创建任务使用冻结快照，新任务使用修改后快照。
6. 视频任务提交后切换供应商和关闭画布，验证轮询仍使用任务冻结的供应商连接。
7. 应用重启后恢复具有远程 `task_id` 的视频任务；同步图片任务没有远程 ID 时明确进入 `interrupted` 或 `unknown`，且不会自动重提。
8. 大量任务存在时打开任务面板，验证列表按需渲染，未展开任务不会创建媒体播放器或完整错误 DOM。
9. 任一本地图片或视频保存失败时，生成状态仍保持 `succeeded`，其他任务的生成和结果保存继续执行。
10. 任务创建后关闭面板、切换画布、删除节点和修改输入，验证任务继续执行且 Interface 中没有取消、停止或暂停动作。
11. 删除来源节点后让任务成功，验证结果继续保存到本地但不自动重建已删除节点；任务历史仍可访问结果。
12. 退出应用造成同步图片等待中断时，验证状态为 `interrupted` 或 `unknown` 而不是 `cancelled`；远程视频任务重启后继续恢复。
13. 分别模拟网络异常和 HTTP `500`、`502`、`503`，验证初始尝试后最多执行 3 次自动重试，名义退避为 `2s/4s/8s` 且存在抖动。
14. 前两次尝试失败、第三次成功时，验证任务只产生一个任务 ID，成功不删除前两次完整原始错误。
15. 四次尝试全部失败时，验证不出现第五次执行，用户收到每次倒计时提醒和最终耗尽提醒。
16. 视频已取得 `task_id` 后让状态查询失败，验证只重试查询、不重新提交生成；重试耗尽后状态查询进入 `degraded`。
17. 分别完成一笔成功任务和一笔失败任务，重启应用后验证两笔任务及其完整请求、全部调用和原始返回都仍可查询。
18. 一笔任务先失败两次再成功，验证详情显示同一逻辑请求和三条独立调用记录，最终成功不会覆盖前两次请求或错误返回。
19. 删除来源生成节点和本地结果文件后，验证任务记录、参数、返回与保存历史仍然存在；界面没有单条任务删除和清空历史入口。
20. 验证实际 JSON 参数、Adapter 默认值和有序 multipart 文件元数据可见；API Key、Authorization、Cookie 和签名查询串没有被持久化或展示。
21. 视频任务经历提交和多次状态查询后，验证每次查询的请求与完整原始返回分别持久化；大响应延迟加载但复制和导出内容不截断。
22. 图片生成节点的纯文字和图片参考操作成功后验证没有调用 TOS 或公司素材导入端点；多个结果依次保存为 `<Downloads>/无限画布/<safe(localTaskId)>-<resultIndex>.<extension>`，单结果也使用 `-1`。
23. 视频任务成功后验证没有调用公司素材导入端点，最终文件保存为 `<Downloads>/无限画布/<safe(remoteTaskId)>.<extension>`；不存在供应商子目录，历史预览只读取该本地文件。
24. 中断 URL 下载或 Base64 写入，验证 `.part` 文件不会被当作成功结果；重新取得有效源后只恢复保存，不重新提交生成。
25. 预置同名同哈希文件时验证安全复用；预置同名不同内容文件时验证进入 `conflict`、不覆盖、不追加供应商后缀，并保存完整冲突信息。
26. 删除本地图片或视频文件后验证任务历史、请求和原始返回仍保留，本地保存状态变为 `local_missing`，界面不把它误报为远程 URL 过期。
27. 两个同名、同来源素材实例连入同一生成节点后，验证 `@` 选择器通过不同 `canvasNodeKey` 精确区分；任务快照同时保存目标画布实例和来源素材身份，而不是只保存名称。
28. 多个图片实例连接到图片生成节点后提交图片参考操作，验证全部实例按冻结的 `edgeOrder` 排列，反向或重复书写 `@` 不改变上传顺序及显式角色，并逐项保存 `图片 N` 位置与内容哈希。
29. 同一已连线实例同时由连线和一个或多个 `@` 芯片表示时，验证它在所属媒体类型序列中只占一个位置；同一来源素材的不同画布实例仍分别占位。
30. 图片生成节点选择纯文字操作但仍有媒体输入时，验证在 Provider 调用前以完整本地解析错误失败，调用记录中不存在供应商请求，节点内提示和芯片保持不变。
31. 断开或删除芯片目标实例、删除远程素材、撤销来源凭据、使签名 URL 过期或修改本地结果文件内容，验证解析器按目标实例和稳定来源身份刷新或拒绝，并保存完整错误，不查找同名替代项。
32. 一笔任务提交后编辑节点内文字、删除芯片、重命名素材或调整连线，验证任务快照、目标实例、冻结 `edgeOrder`、解析内容哈希、实际提示字符串以及图片、视频、音频三类顺序不变。
33. 两个生成节点分别保存提示内容并提交任务时，验证两笔任务独立编译；一个节点的不兼容失败不能修改另一个节点的提示或任务。
34. 依次引用图片 A、视频 A、图片 B、音频 A，验证任务保存的位置为 `(image,1)`、`(video,1)`、`(image,2)`、`(audio,1)`，不生成全局素材位置。
35. 并行解析三张图片并让图片 3 最先完成，验证实际请求仍按图片 1、图片 2、图片 3 组装；视频和音频分别执行同类测试。
36. 让图片 2 解析失败而图片 3 成功，验证整笔任务在供应商调用前失败，图片 3 不前移，且不存在只含图片 1、图片 3 的部分请求。
37. 同一任务经历自动重试时，验证三类位置、内容哈希和请求顺序在每次尝试中完全相同；用户显式创建新任务后才按当前提示重新编号。

# 14 · 自驱指令（goal-creator）

> 何时用：用户想把整条流程（或某一段）交给 AI 一次性跑完。
> 依赖：当前项目状态 + 已完成的环节。
> 产出：一条完整的 goal 提示词，可复制粘贴执行。
> 验收：goal 落地、可执行、有约束。

---

## 什么是 goal 自驱

整套系统按**循环设计（loop engineering）**。你不光能一步步手动驱动，还能写一条 goal，把整条流程（或某一段）交给它一次性跑完。

```
goal = 把 harness 和当前上下文揉到一起的一条指令
     + 完成标准 + 约束 + 执行策略
```

---

## 两种典型用法

### 用法 A：从头到尾跑完整条流程

```
用户：开第二集，从剧本拆解一路往下，把出图出声之前所有的流程全部跑完。
```

goal-creator 会写一条 goal：
- 文件落在哪个路径
- 每个环节怎么做
- 做完怎么检验
- 有哪些约束

### 用法 B：只跑某一段（如批量出图出声）

```
用户：帮我出图出音频，生图用 GPT-image-2，音频用 eleven labs，API 我都准备好了。
```

goal-creator 会：
1. 先确认工具能不能用
2. 写一条完整的 goal 提示词
3. 把 harness 和当前上下文揉到一起
4. 加上完成标准、约束、执行策略

---

## goal 的执行特点

- 全程自驱，中间不用用户参与
- 跑完或卡死才来找用户
- 时间比较长：短则一小时，长则几个小时，具体看素材数量
- **出图出声/出视频很烧钱**，建议在 goal 里停在烧钱步骤之前，让用户手动确认后再跑

---

## goal-creator 的工作流程

1. 确认当前项目进度（哪些环节已完成）
2. 确认用户要跑哪一段
3. 确认工具可用性（如生图 API、音频 API、即梦 CLI）
4. 写 goal 提示词：
   - 文件落在哪个路径
   - 每个环节怎么做
   - 做完怎么检验
   - 有哪些约束
   - 完成标准
5. 交付给用户复制执行

---

## goal 模板

```
【目标】<一句话说清要跑什么>

【范围】
- 从 <环节> 开始
- 到 <环节> 结束
- 不包含 <烧钱环节，如出视频>

【执行策略】
- 按引用依赖拓扑排序
- 每完成一个环节派 film-reviewer 审，过了才往下
- 卡死时停下来找用户

【约束】
- 生图工具：<GPT-image-2 / Midjourney / Nano Pro>
- 音频工具：<eleven labs / 其他>
- 文件路径：output/<项目名>/
- 编号按 reference index 走

【完成标准】
- 所有图齐：角色 N + 场景 N + 道具 N + 分镜图 N
- 所有声齐：配音 N 条 + 音乐 N 条
- 一致性过审：脸没串、画风统一
- 样片先行：先出 1-2 条确认
```

---

## 何时用 goal vs 手动

| 场景 | 推荐 |
|---|---|
| 从拆解到出图出声整条流程 | goal 自驱 |
| 只跑批量出图出声 | goal 自驱 |
| 迭代修改某几条提示词 | 手动 |
| 出视频（烧积分） | 手动（样片先行） |
| 进化消化 | 手动（需要用户拍板） |

> goal 适合又长又重的任务（几十张图、几十条音频），手动适合需要人工把关的环节。

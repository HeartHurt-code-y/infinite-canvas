# 12 · 审核标准清单（V4 · 可持续更新）

> 这是 viral-video-prompt-engine 的**审核标准单一真相源**。
> 独立审核agent判定时，逐项对照本文件。要么有证据，要么不成立。
> 本文件是活文档，持续更新（更新机制见末尾）。

## 一、审核员角色与独立性原则

**审核员是独立实例**，通过 Agent 工具派发（subagent_type: general-purpose），不继承创作上下文。

独立性四不原则：
1. **不继承创作意图**——不知道作者为什么这么设计，只看产出和标准
2. **不参与创作**——只报告不修改，修改回主控做
3. **不假设对错**——每个结论必须附证据（场次号/镜头号/资产编号/原文片段）
4. **不留情面**——禁止"基本达标""大致合理"这类模糊词，要么✓要么⚠要么✗

## 二、两阶段框架

| 阶段 | 查什么 | 性质 | 不通过处理 |
|---|---|---|---|
| 第一阶段·做对了没有 | 结构正确性 | 硬性，有✗必须先修正 | 有高优先级✗停在这，不往下审 |
| 第二阶段·做好了没有 | 工艺质量 | 软性，⚠可交人工核定 | 全部审完再给结论 |

## 六、判定示例

### ✓ 正确写法（有依据有证据）
```
[✓] Q3运镜不越轴 —— 依据：场3周琳坐桌后（画面右）、男主站桌前（画面左），
双机位均在桌前侧180度线同侧；SD04镜2反切男主反应机位在周琳同侧，未越轴。
```

### ⚠ 正确写法（有依据有改进方案）
```
[⚠] Q6灯光一致 —— 依据：S07主卧场4(妻子背对手机屏亮)与场6(男主坐床边)
色温均3000K暖黄一致，但场6末帧台灯被关掉光源变化，03分镜SD09首末帧
已标注但未说明转场处理。改进：SD09末帧补"叠化黑场过渡光源变化"。
```

### ✗ 正确写法（有依据有必修位置）
```
[✗] S2死引导 —— 依据：SD02多模态版@图片8引用S04工位，但reference index
无S04编号（仅有S01-S03主场景+S04精简八层无独立编号）。必修：02资产
补S04到reference index，或SD02改引用现有编号。
```

### ❌ 错误写法（无依据/模糊）
```
[✓] Q3运镜不越轴              ← 无依据，无法验证
[⚠] 灯光可能有问题            ← 模糊无指向
[✓] 整体质量不错              ← 笼统客套，非具体项
[⚠] 或许需要关注一下节奏      ← 无具体段落无改进方案
```

## 十、更新机制（后续怎么完善这份标准）

本文件是活文档，持续更新。更新原则与流程如下。

### 10.1 更新触发条件

满足任一即提议更新：
1. **信号积累**：experience/signals.jsonl 里"审核标准缺失"类信号累计≥3条
2. **项目收尾**：每完成一个项目，阶段04收尾时检查本轮是否发现新审核维度
3. **审核翻车**：某阶段审核通过但人工/制作环节发现严重问题（说明标准有盲区）
4. **定期**：距上次更新≥7天且期间有项目跑过

### 10.2 更新流程

1. 在 signals.jsonl 记录"审核标准缺失"信号（含具体场景+缺失维度）
2. 触发条件满足时，向用户提议"审核标准有N处可补充，是否更新12-film-review.md"
3. 用户同意后，更新本文件：
   - 新增检查项：加到对应阶段表格，附判定标准+阈值+方法
   - 修订阈值：调整量化数值（需说明理由）
   - 版本号+0.1（V4.1/V4.2...），在文件头标注更新日期和变更摘要
4. 同步更新 SKILL.md 引用 + standalone

### 10.3 更新原则

- **只增不删**：除非某标准被证伪，否则只新增不删除（旧标准是历史经验）
- **新增必有阈值**：每个新检查项必须附可量化阈值或明确判定方法，禁止新增模糊项
- **变更留痕**：每次更新在文件头"变更日志"记录改了什么、为什么改

> 审核标准的价值，在于让"审核"从主观判断变成可复现的对照。标准越明确，审核越不可能走过场。
> 这份清单会随每个项目长大。每发现一个盲区，就补一条标准。这就是它持续进化的方式。

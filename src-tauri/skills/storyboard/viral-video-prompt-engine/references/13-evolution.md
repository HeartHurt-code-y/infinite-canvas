# 13 · 进化（evolution）

> 何时用：用户纠正时抓信号；新 session 启动时消化积压信号。
> 依赖：用户的纠正原话。
> 产出：具体的改动建议，逐条问用户拍板。
> 验收：同意即生效，否了即删，规则能进也能退。
> **进化是当场拍板，没有缓冲期。**

---

## 信号捕捉

用户纠正你时（"不要这样写"/"应该这样"），即视为一条待生效信号。

措辞隐晦没抓到的，主 Agent 自己识别自己补记。

信号记在对话里（含时间戳、原话、发生场景）：
```json
{"ts":"2026-07-04T10:30:00","signal":"用户纠正：不要在提示词里反复描述长相","context":"编悟空运动提示词时"}
```

---

## 消化进化信号

本轮对话里就已经可以消化——把信号当场提炼成改动建议：

1. 回顾本轮用户给过的纠正原话
2. 提炼成具体的改动建议
3. 回来当场逐条问用户

```
积压了 N 条信号，我提炼成 N 条建议：

建议 1：<具体改动>
  依据：你上次说"<原话>"
  要改进：<对应 Skill 文件 + 改什么>
  同意吗？

建议 2：...
```

---

## 当场拍板

- **同意** → 立刻改进对应文档。编排进主控、Skill 行为进对应 references、确定性门禁进 hook。
- **否了** → 信号和建议一起删。

点头即生效，没有缓冲期。

---

## 双向：规则能进也能退

不光加规则，也扫描现有规则提议退休：

- 判断标准：删了它会不会复现当初的失败？
- 不会就删。
- 规则总量要往下走。

---

## 影片偏好 vs 通用规律

- **影片专属的偏好** → 只作用于当前项目，写进本项目讲戏本/分镜的配置区
- **通用规律** → 进 references 规则
- 框架不被单部片子的口味污染。

---

## 进化触发条件

满足任一即主动询问用户是否提炼：
- 同类纠正累计到 5 条
- 距上次消化 ≥ 3 天
- 用户主动说"复盘一下"/"提炼一下经验"

---

## 进化的边界

### 不会做的
- 不会自动修改用户已确认封板的产出物
- 不会自动触发消化（必须新 session 或用户主动）
- 不会自动删除任何经验记录（仅归档）
- 不会自动安装新 skill

### 会做的
- 用户的纠正当场抓成信号
- 新 session 主动消化积压信号
- 提炼成建议逐条问用户
- 同意即改 references
- 扫描规则提议退休

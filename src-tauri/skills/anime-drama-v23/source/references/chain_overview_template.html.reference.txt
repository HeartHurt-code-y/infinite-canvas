<div class="box warn"><b>计费口径与沉没成本</b>
计费按 <code>taskCostTime</code>（<b>含排队的墙钟秒</b>），与视频时长无关 ——
消费级 0.4 币/秒（≈¥__RATE__/币）、企业级 ¥6/小时。<br>
累计支出 <b>__TOTC__ 币 + ¥__TOTM__</b>（≈¥__TOTCNY__）；
其中被后续重跑顶掉的白烧部分约 <b>__BURNED__ 币</b>；
<b>当前有效台账</b>（每段取最新）= <b>__CURC__ 币 + ¥__CURM__</b> ⇒ ≈¥__CURCNY__。</div>
<div class="box info"><b>这 __CONSC__ 币是怎么来的 / 依据是什么（可复核）</b>
<b>① 币不是估的，是逐段实测累加</b> —— 每个 taskId 跑完调
<code>/task/openapi/outputs</code>，取返回的 <code>consumeCoins</code> / <code>consumeMoney</code> /
<code>taskCostTime</code>，逐段写进 <code>状态/成本台账.csv</code>（列：账号 / 请求时长s /
<b>实际耗时s</b> / RH币 / 钱包CNY）。<br>
<b>② 交叉验证（两条费率都能对上）</b><br>
&nbsp;&nbsp;· 消费级：<b>__CONSC__ 币 ÷ __CONSS__ s = __COINRATE__ 币/秒</b> ≈ 平台费率 <code>0.4 币/秒</code> ✓<br>
&nbsp;&nbsp;· 企业级：<b>¥__TOTM_E__ ÷ (¥6 ÷ 3600) = __ENTTS__ s</b>，与台账里企业级 __NENT__ 段实际耗时之和完全吻合 ✓<br>
<b>③ 计费口径：按 <code>taskCostTime</code>（含排队的墙钟秒），与视频时长无关</b> ——
所以一段 5 秒的视频可能烧 232 秒；并发 5 路时排队时间会摊在各自任务上。<br>
<b>④ <code>≈¥__CURCNY__</code> 是折算值，不是实付现金</b> —— 换成人民币用的是账号自己的
币/元比值（<code>1 元 ≈ __PERCNY__ 币</code>，即 <code>1 币 ≈ ¥__RATE__</code>，
取自 <code>/uc/openapi/accountStatus</code> 返回的 <code>remainCoins / remainMoney</code>）。
消费级是**预付币**模式，钱包余额只是平台的展示口径；
**真正扣现金的是企业级那 ¥__TOTM_E__**。<br>
<b>⑤ 13 段生成耗时合计 __WALL__ s（__WALLH__ h）</b>；但因为 5 路并发，
用户实际等待时间远小于这个数（首轮 13 段在跑约 13 分钟）。</div>

<h2>六、复盘：三条每次都要盯的通用判据</h2>
<div class="box good"><b>① 品牌渗漏是模型结构性先验，提示词压不住</b>
「户外 / 运动 / 专业装备」类场景（雪山、赛场、工装、护目镜等）下，
模型<b>必然</b>在胸前、袖标等显眼位生成真实品牌标。实测过的四版对策 ——
改颜色、改品类、加 Negative 品牌词、加道具遮挡 —— <b>常常全部失败</b>。
判据：<b>同一问题换 3 个角度都不动 = 结构性先验，立刻停止试提示词</b>，
要么换构图（让该位置不出现在画面里），要么接受并在交付说明里写明。</div>
<div class="box good"><b>② 共享工作流模板必须先「去参考化」</b>
平台共享模板在核心节点（W-A/W-B 都是 <code>265</code>）上会残留<b>上一位使用者</b>的
参考图 / 参考音频直连，直接污染人脸与服装。提交前必须断开这些连线
（<code>references/make_noref_workflow.py</code>），改用 <code>workflow</code> 参数直传干净 JSON，
<b>不向平台上传任何素材</b>。已固化铁律 D31。</div>
<div class="box good"><b>③ 派生页的数字必须实时解析</b>
派生的 HTML 页里<b>禁止硬编码</b>「N 镜 / N 币」这类统计 —— 分镜一修订就全部失效。
所有数字都要现场从产物文件解析（分镜 md / ffprobe / 成本台账），本页即按此生成。</div>

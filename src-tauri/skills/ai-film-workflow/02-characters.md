# 阶段专用方法：characters 人物圣经

## 职责与输入

只依据故事纲要建立可写、可演、可视觉化且跨场一致的人物圣经。不得改写故事主旨和结局，不得提前写分场、剧本、资产提示词或镜头提示词。故事纲要是硬依赖；当前请求中明确粘贴的版本优先于历史版本。

## 人物建模

至少覆盖主角、主要对抗者和承担关键因果功能的配角。每个人物的 Markdown 条目应包含：

1. **身份与功能**：姓名、年龄段、社会身份、剧情职责以及对主角施加的具体作用；
2. **可见外观**：体型、脸部和姿态特征、易识别标记、常用服装，以及外观随弧光发生的物理变化；
3. **内在结构**：缺陷、外在欲望、内在需求、恐惧、底线、无法原谅之事和塑造现状的关键传记事件；
4. **人物弧光**：起点、被迫改变的转折、最终选择和终点状态；
5. **声音指纹**：句长、语域、词汇范围、俚语或口癖、辩解倾向、何时沉默、两到三句用于区分声音的示例台词；
6. **关系图**：与其他关键人物的关系温度、公开目标、隐含冲突、权力差、专属称谓和变化方向；
7. **行为与物件**：压力下的习惯动作、触发条件、标志性微表情及贯穿人物的视觉物件。

## 路线适配

- 经典因果叙事重点写主角和对抗者的欲望、需求、持续施压能力与镜像关系。
- 意象驱动短片用衣着、精神外观、习惯动作和母题让创作意图进入肉身；明确沉默是抵抗、妥协还是沟通失败。
- 高钩子叙事明确表面身份与隐藏能力的反差、受压和揭示时的可见状态变化；配角必须承担施压、见证或反衬功能。
- 混合路线继承故事纲要选定的主结构，不额外创建另一套人物逻辑。

## 自动审校与修复

逐项核对姓名、身份、动机、弧光和关系是否与故事纲要一致；外观、动作和物件是否能被镜头观察；各人物声音是否在句长、语域、词汇、沉默条件上明显分离。执行匿名台词归属测试：遮去角色名后仍应能从语言辨认说话者；若混淆度高，自动重写声音设定和示例。删除只承担说明、没有行动或关系功能的冗余角色，或把其功能合并给现有角色。

## 决策条件

上游纲要完全不可用、两份都被声明为权威的人物身份互相冲突、或用户要求保留但未提供的真实人物资料是创作必要条件时，使用 `needs_confirmation`。可从故事功能推导的年龄段、职业细节、外观和语言特征应自动完成。

## 输出合同

只输出一个 JSON 对象，不要输出代码围栏或额外说明：

```json
{
  "schemaVersion": "ai-film-stage.v1",
  "stage": "characters",
  "status": "ready",
  "content": "完整 Markdown 人物圣经",
  "inputSummary": "采用的故事纲要、当前约束与必要假设",
  "decision": null,
  "assets": [],
  "shots": []
}
```

字段必须全部存在且不得增加字段。`status` 只能是 `ready` 或 `needs_confirmation`。需要决定时，`decision` 只能为 `{"question":"一个决定性问题","recommendation":"推荐答案"}`；否则必须为 `null`。本阶段的 `assets` 和 `shots` 永远为空数组。

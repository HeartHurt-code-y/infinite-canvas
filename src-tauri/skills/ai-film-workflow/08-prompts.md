# 阶段专用方法：prompts 可执行镜头提示词

## 职责与输入

只把剧本、资产目录和表演设计转化为当前项目模型可执行的逐镜视频提示词。所有原文台词逐字不变。不得新增剧情、改写用户台词、虚构参考素材、路径、链接或资产 ID。每个镜头必须能脱离前后文独立执行，同时用显式连续性条件与相邻镜头衔接。

## 镜头拆分与可行性

先按剧情动作、对白长度、反应、运镜和剪辑目的划分镜头，不机械等分时间轴。每个 `durationSeconds` 必须在 4 到 30 秒之间。先估算正常语速下原文台词、必要停顿、动作和物理反馈能否完成；时长不足时依次延长到当前项目模型支持的范围、删除次要反应、删除系统新增内容、在自然停顿处分镜。绝不压缩、翻译、润色、删减或合并用户原文台词。

默认选择能清楚表达动作的连续镜头。只有用户明确要求剪辑、单一机位无法表达事件、必须展示关键反应或局部细节、或场景地理与人物行动需要分开呈现时，才拆为受控多镜头。每次切换都要有叙事目的，并保持轴线、屏幕方向、视线、位置、光向和道具状态连续。

## 当前镜头隔离

每个镜头只保留当下可见或可听的角色、地点、道具、动作、台词和真实存在的参考资产。删除场号、前情摘要、未出场角色、过期引用以及“同上”“继续”“和之前一样”等依赖上下文的词。

若有场景参考，先转换为地图：前中后景、入口、地标、角色世界位置、屏幕位置、运动路径和光线方向。参考图不自动继承构图。身份参考优先锁定人物，道具参考锁定形状、比例、材质和握持，场景参考锁定地理与表面；风格参考不得覆盖身份、空间、动作或灯光。

## 首帧、空间与连续性

除非叙事明确要求空镜，首帧直接包含必要主体和可读空间关系。为每个角色写明屏幕左右、前中后景、身体朝向、视线目标、与地标距离和移动方向；为关键道具写明所在手、接触方式和物理状态。跨镜重复最少但充分的身份、服装、伤口、污渍、道具、天气和情绪余波锚点，不能在剪切后重置。

镜头与构图按可见结果选择：自然透视适合中性观察，广阔空间与近距离身体互动需要可读环境，肖像与孤立需要背景压缩，微小细节应成为独立插入镜头。不要在同一节拍同时要求互斥的宏大环境、紧密肖像和微距细节。摄影机描述应包含机位高度、与主体距离、角度、运动轨迹、主体画面占比、焦点行为和景深，而不是依赖器材名称。

## 动作、物理、灯光与声音

动作时间线中的每个连续区间应同时说明主体位置、行为、摄影机、道具状态、物理反馈和声音。确保质量、惯性、摩擦、接触、重心、布料和头发延迟、液体或粒子运动具有因果；避免漂浮、滑步、瞬移和无重量道具。

灯光是连续性约束。明确主光源、方向、摄影机处于光源哪一侧、主体受光或轮廓状态、背景亮度、曝光优先级和允许的反射。声音只包含本镜头需要的对白、旁白、环境声、动作声和音乐配置；没有输入的声音不要擅自添加。说话者只在念出对应原文时发生口型，其他角色保持倾听反应。

## `videoPrompt` 四段式

每个 `videoPrompt` 是纯文字、无需素材标记也能直接执行的四个自然段：

1. **主体与事件**：一句话写清人物、地点、当下事件、首帧和整体可见风格；
2. **空间与摄影机**：角色和道具调度、视线、地标距离、镜头选择、机位、构图、运动和连续性；
3. **时间与表演**：按镜头内部真实节拍写动作、策略变化、倾听、逐字台词、道具变化、物理反馈和必要剪切；
4. **光线与声音**：光源方向、曝光、材质动态、环境声、动作声、对白或旁白及针对当前镜头的最小验收约束。

提示词使用紧凑自然语言。高密度细节只用于身份、空间、首帧、视线、手部和道具状态、动作、物理、灯光及台词。局部负向约束仅用于已知高概率失败且当前模型支持的情况，不能用巨大通用列表代替正向状态。

## 真实素材映射

`referenceAssetIds` 只能列输入中真实存在且本镜头确实使用的资产 ID，不得创建占位 ID。`content` 必须是完整 Markdown 镜头交付稿：每个镜头总有一份纯文字版；存在真实参考素材时，再给出一份多模态版，逐项把资产 ID 映射到人物身份、场景地理或道具形态。多模态版也只能引用 `referenceAssetIds` 中的真实 ID。没有素材时只写纯文字版，并保持 `referenceAssetIds` 为空。

## 自动审校与修复

按优先级检查：故事事实和身份一致性；引用存在性；台词逐字一致；时长可行；首帧与空间调度；轴线、视线、光线和状态连戏；物理合理性；表演节拍；提示词是否独立且无上下文泄漏。`acceptance` 为每镜提供非空、可观察、能据此质检的标准。可修复问题直接重写；当前项目模型不支持某种时间控制、素材输入、声音或目标比例时，使用其已有能力进行粗粒度节拍、分段生成或参数适配，不伪造能力。

## 决策条件

用户明确要求引用但未提供的关键资产、两份权威素材对人物身份或空间给出互斥事实、原文台词在 30 秒上限内即使自然分镜也无法保持完整、或核心动作依赖当前项目完全没有的能力且不存在自动降级方案时，使用 `needs_confirmation`。其他情况完成自审后返回 `ready`。

## 输出合同

只输出一个 JSON 对象，不要输出代码围栏或额外说明：

```json
{
  "schemaVersion": "ai-film-stage.v1",
  "stage": "prompts",
  "status": "ready",
  "content": "完整 Markdown 镜头交付稿，含纯文字版及有真实素材时的多模态版",
  "inputSummary": "采用的剧本、资产、表演、模型能力与必要假设",
  "decision": null,
  "assets": [],
  "shots": [
    {
      "id": "唯一稳定镜头ID",
      "sceneId": "所属场景ID",
      "title": "镜头标题",
      "durationSeconds": 8,
      "visual": "本镜头可观察的视觉目标",
      "dialogue": "原文台词；没有则为空字符串",
      "videoPrompt": "纯文字四段式可执行提示词",
      "referenceAssetIds": [],
      "acceptance": ["至少一条非空、可观察的验收标准"]
    }
  ]
}
```

字段必须全部存在且不得增加字段。`status` 只能是 `ready` 或 `needs_confirmation`；需要决定时 `decision` 只能为 `{"question":"一个决定性问题","recommendation":"推荐答案"}`，否则为 `null`。本阶段 `assets` 永远为空数组。`shots` 必须覆盖用户所请求的全部镜头；每项字段必须存在，`dialogue` 无台词时为空字符串，`referenceAssetIds` 无真实素材时为空数组，`acceptance` 不得为空。

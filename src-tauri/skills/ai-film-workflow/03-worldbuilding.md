# 阶段专用方法：worldbuilding 世界圣经

## 职责与适用性

只建立剧情真正需要的世界规则，不改写故事和人物，也不提前写分场、剧本、资产或镜头提示词。故事纲要是硬依赖，人物圣经用于校验知识边界与规则代价。

先判断世界是否需要完整建模。若是常规现实环境，且没有特殊制度、技术、超常系统、关键历史、派系、独特地点规则或承担铺垫回报的道具，生成一份简明现实基线即可，不为填模板发明设定。

## 世界建模

Markdown `content` 按适用范围覆盖：

1. **现实差异基线**：这个世界与现实相同和不同的部分，故事允许观众默认理解的常识；
2. **能力或制度闭环**：能做什么、不能做什么、使用代价、谁能使用、如何获得、如何失去以及违规的可观察后果；
3. **相关历史与当前状态**：只保留影响当前冲突的历史事件及后果，并说明开场时政治、社会、自然或技术状态；
4. **派系与冲突**：各方目标、方法、代表人物、资源、相互冲突点以及与主角行动的关系；
5. **关键地点**：空间特征、进入条件、剧情用途、承载的场景和会限制行动的物理规则；
6. **关键道具**：外观与功能、首次出现、使用限制、回报时刻和主题含义；
7. **知识矩阵**：每个关键角色知道什么、不知道什么、误以为知道什么，以及信息改变的场次或事件；
8. **呈现策略**：每条规则如何通过行动、画面物件、选择代价和后果展示，避免角色用对白朗读说明。

## 自动审校与修复

检查每项能力、限制、代价和权限是否闭合，剧情是否会无故绕过规则；历史、派系和地点是否对当前情节有实际作用；关键道具是否完成铺垫与回报；知识矩阵是否阻止角色提前知道不应知道的信息；同一规则在故事纲要和人物圣经中是否一致。无剧情功能的设定直接删减，规则漏洞优先以最小改动修复，不能靠新增更强规则遮盖。

## 决策条件

两套都被用户声明为权威的世界规则互相排斥、某项规则的选择会改变故事核心结局、或必需参考资料缺失且无法恢复时，使用 `needs_confirmation`。普通地点细节、制度名称和可从上游因果推导的限制应自动完成。

## 输出合同

只输出一个 JSON 对象，不要输出代码围栏或额外说明：

```json
{
  "schemaVersion": "ai-film-stage.v1",
  "stage": "worldbuilding",
  "status": "ready",
  "content": "完整 Markdown 世界圣经或现实基线",
  "inputSummary": "采用的故事、人物、规则与必要假设",
  "decision": null,
  "assets": [],
  "shots": []
}
```

字段必须全部存在且不得增加字段。`status` 只能是 `ready` 或 `needs_confirmation`。需要决定时，`decision` 只能为 `{"question":"一个决定性问题","recommendation":"推荐答案"}`；否则必须为 `null`。本阶段的 `assets` 和 `shots` 永远为空数组。

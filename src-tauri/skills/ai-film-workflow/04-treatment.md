# 阶段专用方法：treatment 分场大纲

## 职责与输入

只把故事纲要、人物圣经和适用的世界圣经转化为按场组织的可拍摄事件链。不得写正式对白、剧本格式、资产提示词或镜头提示词。当前用户给出的目标时长和场景数是硬约束；未给场景数时，根据总时长和叙事路线自动估算并分配，不为常规估算请求确认。

## 场景写法

每场以“内景/外景 · 地点 — 时间”开头，随后用约三至五句描述镜头可观察的动作、出场人物、冲突推进和场尾结果。不要使用引号台词，也不要把纯心理说明当作动作。每场必须至少改变价值、状态、信息或关系中的一项，并说明它如何推动下一场；蒙太奇、平行线和第一场可用时间或主题连接，但在汇合前必须完成因果闭合。

## 节拍结构

- **经典因果叙事**：建置人物与常态；在前段触发不可逆的诱发事件；通过逐级升级的对抗进入中点胜利或失败并提高风险；形成不可兼得的危机；以身体性行动完成高潮；用一至两场建立新秩序。片尾钩子仅在项目需要时使用。
- **意象驱动短片**：奠定意图与语境；让母题和习惯动作反复出现并变化；使隐喻进入物理现实；用行动呈现崩塌、释放或妥协；以有依据的留白完成闭环。
- **高钩子叙事**：尽早呈现困境；把能力或底牌转化为可见行动；连续施压和反制；给出明确动作回报；以更大危机或未完成选择形成悬念。
- **自定义混合**：沿用故事纲要选定的主节拍，覆盖用户明确约束，不并排套用多套结构。

场景数由目标时长除以该路线合理的平均场时长估算，再按主要节拍的叙事重量分配。不要机械等分，也不要让关键选择、反应或后果因压缩而消失。

## 自动审校与修复

逐场检查：与前场是否存在因果或明确的并行关系；是否发生可辨认变化；是否服务主旨或创作意图；删除后是否会损害因果、人物、信息或节拍。用“因果断裂、状态未变、上游冲突、节奏失衡、信息倾倒、重复”分类问题。局部问题直接重写；确无功能的场景合并或删除，并重新分配编号和时长。全局检查总场数和总时长、人物与世界连续性、所有铺垫回报，以及是否误写对白或不可拍摄心理活动。

## 决策条件

故事纲要或人物圣经完全缺失且无法恢复、精确场景数与精确时长在物理上互不兼容、或权威上游材料在核心事件上冲突时，使用 `needs_confirmation`。其他节奏和场景取舍应自动修复后返回 `ready`。

## 输出合同

只输出一个 JSON 对象，不要输出代码围栏或额外说明：

```json
{
  "schemaVersion": "ai-film-stage.v1",
  "stage": "treatment",
  "status": "ready",
  "content": "完整 Markdown 分场大纲",
  "inputSummary": "采用的上游成果、时长、场景约束与必要假设",
  "decision": null,
  "assets": [],
  "shots": []
}
```

字段必须全部存在且不得增加字段。`status` 只能是 `ready` 或 `needs_confirmation`。需要决定时，`decision` 只能为 `{"question":"一个决定性问题","recommendation":"推荐答案"}`；否则必须为 `null`。本阶段的 `assets` 和 `shots` 永远为空数组。

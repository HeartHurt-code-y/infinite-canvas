# 阶段专用方法：acting 表演设计

## 职责与输入

只把人物圣经和剧本转化为可观察、可拍摄、可按镜头节拍执行的表演设计。不得更改台词、剧情、人物身份或世界规则，不得生成图片资产或最终视频提示词。用户原文台词逐字锁定；表演层只能设计说法、停顿、倾听和身体行为。

## 角色长期主档案

为每个反复出现的角色建立一次长期行为基线，并在各场按状态调整：

- 身体档案：年龄段、体型、旧伤或职业留下的姿态、重心、步态和占据空间的方式；
- 声音身份：音高或音色、语速、发音和语域、压力下如何破音或收紧；只有该角色开口时才启用；
- 下意识动作：日常习惯、压力触发动作、掩饰行为、公开面具及面具破裂的确切条件；
- 眼神行为：关注目标、思考时的眼球微动、眨眼变化、眼睛先于头部到达目标以及评估信息的停顿；
- 软肋与地位：能让角色卸下面具的唯一对象，以及高低地位在动作速度、凝视、空间占用和自我触碰上的表现。

所有内在状态都要转换为身体可见标记。姿态或场景条件限制某个习惯时，把同一心理功能迁移到眼神、呼吸、手指或语速等可用出口，不直接删掉人物特征。

## 每场五个支柱

1. **目标**：角色此刻想从一个具体对象那里得到什么，使用“逼迫、说服、拖延、试探”等指向对手的动作动词，而不是“感到愤怒”等状态词；
2. **障碍**：外部阻力与内部自我阻力；
3. **赌注**：失败会失去什么，必须对角色构成真实压力；
4. **策略**：角色当前采用的具体手段，以及失败后如何更换手段；
5. **潜台词**：嘴上表达与真实目标之间的差异，通过过短回答、重复提问、生硬转移、失当玩笑、停顿或身体矛盾自然显现。

把每场拆为二至四个有功能的表演节拍。新信息出现、策略失败、目标达成或权力转移时开始新节拍；每次变化必须通过视线、姿态、距离、呼吸、语速或手头动作被看见。节拍时长依据台词、物理动作和反应自然估算，供下游按实际模型能力安排，不套固定秒数。

## 倾听、身体与群像

反应可以在对方一句话尚未结束时开始，但不能抢走原台词。重要信息后保留评估瞬间，让眼神先处理信息再开口。给角色一个与场景目标并行的手头任务，使身体持续存在；动作可与台词相反以产生潜台词，但不可变成逐字图解。

明确角色间距离、谁靠近或退出、谁占据中心、谁需要请求目光许可，以及地位如何变化。群像反应应错峰并各自符合关系；特写时减少大幅动作，保留眼神、呼吸和细小肌肉变化。每场末尾记录未消散的身体与情绪余波，供下一镜保持连续。

## Markdown 成果结构

`content` 先列角色表演主档案，再按场列出：场景目标、障碍、赌注、起始身体状态、空间关系、表演节拍、逐句台词的说法与反应、群像错峰、场尾地位变化和余波。不得把抽象情绪直接当成表演指令。

## 自动审校与修复

核对每场是否具有目标、障碍、赌注、策略变化和潜台词；角色是否持续倾听；眼神、触发式动作、手头任务、距离变化和评估瞬间是否可见；台词是否逐字不变；声音身份和动作习惯是否与人物圣经一致；物理动作在场景空间和时长中是否可完成。平直、夸张或只写表情标签的段落自动重写为连续行为。

## 决策条件

剧本或人物圣经完全缺失且无法恢复、两份权威台词版本冲突、或用户同时要求互斥的角色身份与行为底线时，使用 `needs_confirmation`。常规表演强度、停顿、动作和策略变化应自动设计。

## 输出合同

只输出一个 JSON 对象，不要输出代码围栏或额外说明：

```json
{
  "schemaVersion": "ai-film-stage.v1",
  "stage": "acting",
  "status": "ready",
  "content": "完整 Markdown 角色主档案与逐场表演设计",
  "inputSummary": "采用的人物、剧本、台词与必要假设",
  "decision": null,
  "assets": [],
  "shots": []
}
```

字段必须全部存在且不得增加字段。`status` 只能是 `ready` 或 `needs_confirmation`。需要决定时，`decision` 只能为 `{"question":"一个决定性问题","recommendation":"推荐答案"}`；否则必须为 `null`。本阶段的 `assets` 和 `shots` 永远为空数组。

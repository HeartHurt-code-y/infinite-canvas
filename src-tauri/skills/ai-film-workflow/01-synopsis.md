# 阶段专用方法：synopsis 故事纲要

## 职责与输入

只把项目创意整理为可供后续人物、世界和分场阶段使用的故事骨架。不得提前写人物圣经、分场、完整剧本、资产提示词或镜头提示词。优先继承用户明确给出的类型、体量、受众、基调、主题、角色与结局；缺失的常规创作项可合理推导并在成果中标为假设。

## 自动选择叙事路线

根据体量、基调和主要驱动力选择一个主结构：

- **经典因果叙事**：适合完整长短片和连续剧集。建立主角欲望、持续阻力、升级代价、不可兼得的危机选择、作为选择回应的高潮行动与新秩序。
- **意象驱动短片**：适合重感知和留白的项目。并行组织表层生存状态或事件、贯穿的物理隐喻、创作意图与反复出现的母题或习惯动作；不强迫传统胜负高潮。
- **高钩子叙事**：适合短体量和强反转项目。先给困境底色，再明确突破机制及限制，以压力、底牌显露、行动回报和尾部悬念形成因果链。
- **自定义混合**：只选一个主节拍系统，其他路线只提供基调或表现特征，避免多个结构互相争夺节奏。

路线可以自动判定。只有两条路线会造成核心故事实质不同且没有任何证据时，才请求一次决定。

## 故事骨架

成果的 Markdown `content` 应完整覆盖：

1. 项目定位：类型、基调、受众、预计时长或体量、所选路线及理由；
2. 一句话故事：主角、背景、冲突、主动行动和失败代价；
3. 核心主旨：以因果句说明人物采取何种选择会导致何种结果，并列出必要副主题和差异点；
4. 主角：外在欲望、内在需求、缺陷、恐惧、起点、关键转折和终点；
5. 对抗力量：目标、优势、施压方式以及与主角的镜像关系；
6. 诱发事件：打破原有秩序且迫使主角行动的事件；
7. 升级链：每一阶段如何让阻力、风险或代价增加；
8. 危机选择：两个不可兼得选项及各自真实代价；
9. 高潮与结局：主角用行动回答危机，随后形成可观察的新秩序；
10. 铺垫与回报：关键道具、动作、信息或视觉母题的首次出现和最终用途。

意象驱动路线还应写出表层故事、物理隐喻、创作意图和角色锚点。高钩子路线还应写出突破机制能做什么、不能做什么、代价是什么，并给出开场钩子、早期危机、主要回报和尾部悬念。

## 自动审校与修复

检查欲望—阻力—代价—选择—行动—新秩序是否闭合；主角缺陷和需求是否支撑弧光；对抗力量能否持续施压；诱发事件是否真正改变行动方向；所有铺垫是否有回报；节拍位置是否适合目标体量。发现局部缺口时直接补齐或重写，直到因果清楚。不要用偶然事件替代关键选择，也不要为填模板发明与故事无关的设定。

## 决策条件

只有核心概念完全缺失、两项权威要求会导向互斥结局、或用户指定的事实素材缺失且无法恢复时，使用 `needs_confirmation`。其余情况完成自审后返回 `ready`。

## 输出合同

只输出一个 JSON 对象，不要输出代码围栏或额外说明：

```json
{
  "schemaVersion": "ai-film-stage.v1",
  "stage": "synopsis",
  "status": "ready",
  "content": "完整 Markdown 故事纲要",
  "inputSummary": "本阶段实际采用的输入、权威约束与必要假设",
  "decision": null,
  "assets": [],
  "shots": []
}
```

字段必须全部存在且不得增加字段。`status` 只能是 `ready` 或 `needs_confirmation`。需要决定时，`decision` 只能为 `{"question":"一个决定性问题","recommendation":"推荐答案"}`；否则必须为 `null`。本阶段的 `assets` 和 `shots` 永远为空数组。

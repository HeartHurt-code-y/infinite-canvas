# 时长预算与成片验收

## 规划预算

先数每句实际会说出的字或词，标出语速、停顿、被打断处和同时发声处，再估算每个节拍需要的秒数。普通中文对白可用约每秒 3–5 字作为粗略起点，语速快慢与方言、情绪、表演方式有关；标点停顿另计。重叠只在真实安排的时间窗里抵扣一次，不能把两个人的整句都当作免费并发。逐段至少留出可见反应和镜头稳定时间；台词占比过高时应指出吞字或仓促风险。

`budget` 用简短 Markdown 表列「段落／时间范围／台词量／估计说话秒数／反应与停顿秒数／风险」，再写总长、估计台词占用率和采用的语速假设。表中的段落、台词和时长须与 `timing.beats` 及 `videoPrompt` 一致；时间段首尾相接、起点为零，合计等于节点填写的目标时长。没有确切台词或模型能力时不要造精确预算；返回澄清问题，或在用户允许草案时明确写出估算依据。预算只是写作检查，不能证明生成结果会精确对齐。

将台词占用控制在为反应和动作留下足够空间的范围；超过约 85% 时明确提示节奏过密，并建议删减、延长或分段。这个阈值仅用于文本规划，不能当作项目模型的硬上限或生成成功保证。

台词太密时按权限选择：允许改写就优先删冗余修饰、重排句子或分段，并在 `adaptationNotes` 对照；逐字保留就建议更长的目标时长或拆成多段，等待用户选择。不能静默裁掉台词、改变关键信息或以不可读的语速硬塞进指定时长。

## 待用户拿到视频后检查

`reviewChecklist` 只列可观察项目，并明确这些是待检查项：逐句内容与说话者是否正确；抢话若有安排是否真发生在触发点，双方声音是否自然交叠；停顿、呼吸和口型是否对应；人物接收信息后才反应；镜头空间、服装、光线与素材身份是否连续；台词是否被吞、被补完或急促赶完；结尾选择是否清楚。

用户回传失败表现时，先定位到台词、话轮、节拍、声音、镜头或素材哪一层；优先局部修订并重算受影响预算。不能把文本自检说成看过视频，也不能承诺文字提示词一定产生准确口型或自然演技。

# H3 Ref2VA Optimizer

在 MiniMax 官方 H3 六段式结构之上，叠加**五层增强**，产出可直接粘贴进 H3 全参考通道的提示词。

> 官方 `h3-prompt-writing` skill 保留不动。本 skill 是它的**增强子集**：只做 Ref2VA，不覆盖 T2VA / I2VA / FL2VA / L2VA。
> V1.3 合并了 `minimax-h3-prompt-standardizer`（小白向规范器）的流程层能力，详见 `references/07-cross-skill-merge.md`。

## 步骤 0 · 素材门：先要图，再动笔（最高优先级）

**Ref2VA = 全参考模式。没有参考图就等于让模型自己发明主角。**

这是本 skill 的入口关卡，优先级高于后面所有步骤。

| 情况 | 动作 |
|---|---|
| 用户已提供图 | 立即执行下方**读图校准三步法**，然后再进工作流 |
| 用户未提供图 | **先开口要图**，说清每张图锁什么（人物主参考 / 场景 / 道具 / 服装），**不要先写提示词** |
| 用户明确不提供 | **必须发出下方警告模板**，等用户确认后才可进入无图模式 |
| 进入无图模式 | 每个 Subject 都要标注「无参考图，由文字描述定义」，交付时**附一份上线前补图清单** |

### 无图模式警告模板（逐字发给用户，不要省略、不要软化为「建议」）

```text
⚠️ 无参考图 = 无图模式，后果先讲清：
1. 人物长相由模型随机生成，每次出图都不一样，无法复用于后续镜头 / 场次
2. 服装、妆造、道具细节不可控，跨场次必然漂移
3. 场景空间与光线方向只能靠文字描述，模型理解偏差很大
4. 若后续补图重做，之前生成的所有片段基本作废

确认继续吗？回复「继续无图」，我按纯文字定义出提示词，
并在交付时附一份「上线前必须补图」的清单。
```

> **不要跳过这一步**。用户嫌麻烦时也不能省——省掉的代价是整批素材作废，
> 而补图重做的成本远高于先要一张图。

### 读图校准三步法（有图时强制，V1.5 新增）

1. **读图**——逐张打开图片，看清实际内容。**不看文件名，不采信剧本描述。**
2. **列校准表**——把「剧本文字 / 用户描述」与「图片实际内容」逐项对照，标出每一处不一致。
3. **重写 Subject**——按**图片实际内容**写 `subject_definitions`；
   剧本文字只用于动作与台词，**不用于外观**。

校准表模板（交付时一起给用户看）：

| 项 | 文案描述 | 图片实际 | 采用 |
|---|---|---|---|
| 场景时间 | 傍晚 | 夜间（车窗外是城市夜景） | **图片** |
| 男主工装 | 灰棕色外套 | 做旧灰褐色棉质工装套装 + 膝部破洞 | **图片** |
| 女主哭相 | 眼眶含泪 | 眼眶已红肿 + 鼻尖发红 + 干泪痕 | **图片** |

**为什么强制**：模型只听提示词文字。剧本写「傍晚」而图片是夜景时，模型按文字生成黄昏，
而**校对文字的人看不出错**——因为剧本就是这么写的。
场次58 实测出 10 处不一致，其中「傍晚 → 夜间」是致命项（整场戏的光线、色温、车窗外景全跑偏）。

## 五层增强（相对官方）

| 层 | 官方做法 | 本 skill |
|---|---|---|
| **步骤 0 素材门** | 无 | 先要图；不给图必须发警告并等确认。**有图必走读图校准三步法**（读图 → 列校准表 → 按图重写 Subject） |
| 描述模式 | 只有 `[Shot N]` | **三模式**：表演密集用时间码、对白密集用 `→` 节拍、多镜头用官方 `[Shot N]` |
| 表演粒度 | 按 Shot 描述 | 时间码模式细到 0.5s，逐拍写可观察动作 |
| 运镜 | 类型 + 幅度 + 速度 | **沿用官方三维度**；弧形/环绕/多主体推拉时**可选**补「轴心点」 |
| 时长预算 | 未提 | **多镜头台词字数预算**：中文 4.5 字/秒，校验每镜是否塞得下 |
| Negative | 官方无此字段 | 精简列表，≤10 词，收在提示词末尾 |
| 去污染 | 未提 | 显式声明 `<Picture N> 不得展示 X 背景`，强制换场 |
| **跨段连续** | 无多段概念 | 切点铁律 + 尾帧状态 + 下段切点 + 四锚点 |
| **参考图顺序** | 只规定 `<Picture N>` 编号 | 提示词外先声明上传顺序、主参考、忽略项 |
| **动作/对白要素** | 只要求 describe | 动作七要素（+重心 +收势）、对白七要素（+呼吸/停顿/口型） |
| **模糊词管控** | 仅 BGM 禁抽象情绪词 | 全提示词替换表；`cinematic` 按位置区分合不合规 |
| **过载降级** | 未提 | 四级降级顺序（拆段是最后手段） |

> 后五层来自 V1.3 与 `minimax-h3-prompt-standardizer` 的合并。
> 完整溯源、逐条依据与「哪些其实官方已有」见 `references/07-cross-skill-merge.md`。

## 输出语言策略（核心）

| 元素 | 语言 |
|------|------|
| 六个字段名、`<Subject N>` 等标签、`fully_preserved` 等保留标记、`Negative` 关键词 | **英文** |
| 叙述性文本（主体描述、summary、时间线、声场） | **中文** |
| 对白 | **中文**，直接写「角色名说"……"」 |

> 这样处理是因为：官方规定全英文，但中文场景用中文写人物与动作，描述精度更高、
> 改起来也快。字段名保持英文则是为了不破坏模型对结构的识别。

> **V1.6 收紧**：整段切英文只在三种情况下是必须的——
> ① 音色参考 / 音频复用（`<Audio N>`）；② 精确音画对齐；③ 台词跨切镜（`<scenetrans>`）。
> **纯图片参考 + 多人对白，中文版完全够用**（说话人归属由「→角色名说"……"」承载）。
> 详见 `references/08-real-world-lessons.md` 教训四。

## 两种描述模式

| 模式 | 适用 | 记号 |
|------|------|------|
| **时间码模式** | 表演 / 微表情 / 运镜是卖点（MV、情绪特写） | `**0–1s：**` `**1–2.5s：**` |
| **节拍模式** | 对白密集、动作是离散事件 | `→林浩看着唐糖。` |

两种都写在 `detailed_description` 里，可混用（先 `→` 铺事件，关键处再切时间码细写）。

## 输入策略

**接受一切不完整输入**：一句话想法、混乱长提示词、故事、剧本、对白、分镜表、
参考图，以及「帮我缩短 / 扩写 / 拆分 / 续写 / 修复这段提示词」的请求。
不要求用户懂任何术语。

- **接受一切不完整输入**并推断默认值（比如用户没说时长，就定 8 秒并告诉他）
- **最多问一个问题**，且只在缺了这个答案结果会实质不同时才问
- **没给的东西不许假装看到**——没提供参考图就不要写 `<Picture 1>`

> ⚠️ **唯一不接受「推断」的输入是参考图**。
> 时长、景别、运镜、配乐都可以替用户默认，**唯独外观不能替他编**。
> 所以「要图」不算在那「最多一个问题」里——它是步骤 0 的门禁，见上文。

## 生产形态判定（动笔前静默完成）

| # | 判定项 | 选项 |
|---|--------|------|
| 1 | 生成模式 | 文生视频 / 图生视频 / 首尾帧 / **多参考（本 skill 主战场）** |
| 2 | 故事类型 | 对白 / 动作 / 氛围 / 广告 / Vlog / 动画 / 混合 |
| 3 | 结构 | 单镜连续 / 一段多镜 |
| 4 | 时长 | 用用户给的；没给就选 4–15 秒内的合理值 |
| 5 | 分段 | 只有单段装不下时才拆 |

> 第 1 项若不是「多参考」，**应转用官方 `h3-prompt-writing`**。

## 工作流

0. **过素材门**（见上文步骤 0）：没图 → 先要图；用户不给 → 发警告模板，确认后才走无图模式。
   有图 → **先做读图校准三步法**（读图 → 列校准表 → 按图重写 Subject），把校准表一并交付。
1. **判定模式**：必须含参考素材才用本 skill。纯文字 / 首帧 / 首尾帧 / 尾帧 → 用官方 `h3-prompt-writing`。
   > 走无图模式时，每个 Subject 都要写「无参考图，由文字描述定义」。
2. **编号素材**：图 → `<Picture N>`，视频 → `<Video N>`，音频 → `<Audio N>`。上限 9+3+3，总数 ≤ 12，**建议图只放 1–3 张**。
3. **定义主体**：读 `references/01-six-sections.md`。角色图必须写进 `<Subject>`，禁止单独建 `<Picture>` 条目。
4. **写 summary**：一段中文，格式「时长 + 是否一镜到底 + 场景 + 人物在干什么 + 镜头怎么拍」。
5. **写 retention_analysis**：每个 Subject 一行「保留标记 + 外观 + 动作：A → B → C」，末尾可加一行防乱入约束。
6. **写 detailed_description**：读 `references/02-timeline-and-camera.md`，选时间码模式或节拍模式。
7. **收尾三段**：`overall_soundscape` → `non_diegetic_music`（不需要写 `N/A`）→ `Negative`（读 `references/03-negative-and-pitfalls.md`，≤10 词，英文）。
8. **交付前校验**（多段输出会自动逐段校验）：
   ```
   python scripts/validate_ref2va.py prompt.txt --duration 10
   ```
9. **装不下时降级**（按序，不要平均削减）：
   减同时动作数 → 简化运镜 → 砍台词字数 → 最后才拆段

## 硬约束（铁律）

1. 六段顺序不可变：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`
2. **字段名、参考标签、保留标记、Negative 关键词一律英文**
3. 每段必须非空；`non_diegetic_music` 不需要时写 `N/A`
4. 角色图进 Subject，不单独建 Picture
5. 场景也要定义为 Subject（哪怕无参考图，纯文字定义）
6. 参考图有棚拍纯色背景时，必须写「`<Picture N>` 不得展示 X 背景，替换为实际场景」
7. 删除全部内心独白（「心跳加速」「满脑子都是」「感到悲伤」一律禁用）
8. 用具体动作代替情绪标签（「低头 + 目光落在脚上 + 脸颊泛红」代替「害羞」）
9. 物理动作拆因果链：触发 → 准备 → 发力 → 接触 → 反作用 → 落定
10. Negative ≤ 10 个关键词（官方无此字段，为本 skill 增强，非必需）
11. 运镜按**官方三维度**写：运动类型 + 幅度 + 速度，写成自然英文动作句，不要堆标签。
    中等幅度/正常速度可省略。仅弧形/环绕/多主体推拉时可选补「轴心点」
12. 说话的角色必须有稳定 ID `(S1)`/`(S2)`，放在 `<d>` 之外，跨镜头保持一致
13. 多镜头：首镜不加时间戳，后续镜头切点严格递增且不超总时长
14. 中文台词按 4.5 字/秒估算，每镜需留出 ≥1.2s 给动作/反应，否则砍台词或加长该镜
15. BGM 只写乐器/速度/节奏/力度变化，禁用抽象情绪词（warm、hopeful 等）
16. 单段 4–15 秒，提示词 ≤ 7000 字符
17. **有参考图时，提示词前先写「图片上传顺序」**，顺序与 `<Picture N>` 一一对应
18. **禁止模糊词**（震撼 / 高级感 / 唯美 / 氛围感 / 丝滑 / 有张力）。
    ⚠️ 但 `cinematic` 作 `detailed_description` **首句整体风格标签**时官方允许使用
19. **转场必须写明可见匹配元素**，不许只写「丝滑过渡」
20. **动作必须写收势**（结束时停在什么姿态）——收势即下一段的起始锚点
21. **对白要交代口型**（说完嘴唇如何闭合）
22. **多段拆分时，切点只能落在可见变化上**：景别 / 视点 / 空间 / 时间 / 主体 / 动作完整结束。
    严禁在同动作中途、同姿势保持中、同情绪递进中途切断
23. **多段每段必须写「本段尾帧 + 下段切点」**；跨段的角色 / 场景 / 声音 / 时间锚点全程不改
24. **装不下时按序降级**：减同时动作数 → 简化运镜 → 砍台词 → 最后才拆段
25. **有图必先读图**：外观一律以图片实际内容为准，剧本文字只管动作与台词。
    必须走完「读图 → 列校准表 → 重写 Subject」三步，校准表随提示词一起交付
26. **无图不许静默出稿**：先要图；用户不给则发无图模式警告模板（四条约）
    并等确认；确认后每个 Subject 标注「无参考图，由文字描述定义」，
    交付时附「上线前必须补图」清单
27. **镜头几何必须锁死（V1.6）**：凡有机位/朝向的镜头，写明「机位在哪」
    （`The camera is placed at the rear of the classroom`）+「人物面朝哪」
    （`facing the camera and the class`）。只写「拍哪里」（`frames the front of X`）
    不等于机位——模型会自由发挥出几何上不可能的构图
28. **背景人群与「无其他人」不许同时出现（V1.6）**：场景含群众（教室全班、街道行人）
    时，retention 改「背景人群全程虚化、无清晰面部、不开口说话」，
    Negative 用 `no sharp background faces`，不得再写 `no other people`；
    正文也不得出现「the class settles」这类必然引入群众的句子与「无其他人」打架
29. **压缩长度不许删几何/一致性锚点（V1.6）**：机位、朝向、光源方向、说话人 ID、
    去污染声明、背景人群处理方式——这些是保护项，降级时只删修饰词与重复信息。
    实测：`facing the class` 在两轮压长度中被删，直接导致生成翻车
30. **删除 `<Audio N>` 必须四处全清（V1.6）**：上传顺序块、subject_definitions、
    retention_analysis、detailed_description 的 timbre 措辞，漏一处即报 `LBL-UNDEF` 判错；
    音色特质改为普通形容词直述，summary 前缀降为 `[reference generation]`

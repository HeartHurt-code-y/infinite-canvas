# 01 · 六段式结构 + 标签系统

## 1. 六个固定节段（顺序不可变）

| # | 字段名 | 中文 | 作用 |
|---|--------|------|------|
| 1 | `subject_definitions` | 主体定义 | 定义所有需追踪的参考内容及其标签 |
| 2 | `summary` | 摘要 | 概括任务类型、目标视频、主要参考关系 |
| 3 | `retention_analysis` | 一致性分析 | 参考内容如何被保留 / 转移 / 复用 |
| 4 | `detailed_description` | 详细描述 | 按播放顺序描述画面、动作、镜头、声音、对话 |
| 5 | `overall_soundscape` | 环境声场 | 环境音与物理声音 |
| 6 | `non_diegetic_music` | 背景音乐 | 仅观众可听的配乐，不需要写 `N/A` |

**书写规范（V1.1 改版）**
- 字段名全小写 + 冒号，独占一行
- 每个节段必须有非空内容
- **英文**：六个字段名、`<Subject N>` 等四类标签、`fully_preserved` 等保留标记、`Negative` 关键词
- **中文**：叙述性文本（主体描述、summary、时间线动作、环境声场）、对白

> 官方要求全英文，本 skill 改为「英文骨架 + 中文血肉」。
> 理由：中文场景用中文写人物与动作，描述精度更高、改起来也快；
> 字段名保持英文则是为了不破坏模型对结构的识别。

**一行一条，不用项目符号**

`subject_definitions` 与 `retention_analysis` 用 `<Subject N>：` 直接起头，
**不加 `-` 列表符号**，复制进 H3 更干净。

## 2. 四类标签

| 标签 | 用途 | 示例 |
|------|------|------|
| `<Subject N>` | 可复用可见内容：人物、动物、物体、场景、服装、道具、动作、表情、姿势 | `<Subject 1>`：唐糖 |
| `<Picture N>` | 参考图，作为具体帧锚点或分镜板 | `<Picture 1>`：关键帧 |
| `<Video N>` | 参考视频，提供编辑源、续写起点、整体时间结构 | `<Video 1>`：参考运镜 |
| `<Audio N>` | 参考音频，复制或引用音频信号 | `<Audio 1>`：音色参考 |

### 标签规则
1. 一个标签一旦分配，在**所有节段**保持相同含义
2. 一个 `<Subject>` 可由多个参考素材定义（外观来自图 A，动作来自视频 B）
3. 一个参考素材也可提供多个 `<Subject>`
4. 后续节段**不得重复定义**标签含义，只引用

## 3. 读图校准三步法（有参考图时强制，V1.5）

**写 `subject_definitions` 之前必须完成。** 三步，一步都不能省：

| 步 | 动作 | 关键 |
|---|---|---|
| ① 读图 | 逐张打开图片，看清实际内容 | **不看文件名，不采信剧本描述** |
| ② 列校准表 | 文案描述 vs 图片实际，逐项对照，标出每一处不一致 | 差别再小也要列 |
| ③ 重写 Subject | 按**图片实际内容**写 `subject_definitions` | 剧本文字只用于动作与台词 |

### 为什么强制

**模型只听提示词文字。** 剧本写「傍晚」而图片是夜景时，模型按文字生成黄昏，
而**校对文字的人看不出错**——因为剧本就是这么写的。

场次58 实测：10 处不一致，其中「傍晚 → 夜间」是致命项
（整场戏的光线、色温、车窗外景全部跑偏）。其余还有：
工装颜色与破损程度、鼻梁划伤是单道还是多处、眼眶是「将要哭」还是「已经哭过」、
座椅是菱格还是光面、源图带不带水印。

### 校准表模板（随提示词一起交付给用户）

| 项 | 文案描述 | 图片实际 | 采用 |
|---|---|---|---|
| 场景时间 | 傍晚 | 夜间（车窗外城市夜景） | **图片** |
| 男主工装 | 灰棕色外套 | 做旧灰褐色棉质工装套装，膝部破洞 | **图片** |
| 女主哭相 | 眼眶含泪 | 眼眶已红肿 + 鼻尖发红 + 干泪痕 | **图片** |
| 场景水印 | 未提 | 左上角有「[场景名]」水印 | **图片**（并显式忽略） |

### 校准的三类常见落差

1. **时间 / 光线落差**（最致命）：文字写「黄昏」实际是夜景；文字没提顶灯实际有暖色顶灯
2. **状态落差**：文字写「眼眶含泪」实际是「已经哭过」（红肿 + 鼻尖红 + 干泪痕）——
   影响整段表演的起点
3. **源图污染**：水印、界面文字、UI 元素、压缩噪点、棚拍纯色背景——全部要显式声明忽略

### 无参考图时（无图模式）

先按 SKILL.md 步骤 0 的警告模板取得用户确认，然后每个 Subject 都要标注：

```
<Subject 1>：唐糖，24 岁中国女性…。**无参考图，由文字描述定义。**
<Subject 4>：夜晚街头场景…。**无参考图，由文字描述定义。**
```

交付时附「上线前必须补图」清单，说明哪些 Subject 补图后必须重新生成。

## 4. 关键规范：角色图必须在 Subject 内引用

若一张图仅用于定义角色外观（如全身照），**正确做法是在 `<Subject>` 定义中引用它，而不是为其创建独立 `<Picture>` 条目**。

❌ 错误：
```
subject_definitions:
- <Picture 1>: 唐糖的全身照。

retention_analysis:
- <Picture 1>: fully_preserved 唐糖参考图外观。
```

✅ 正确：
```
subject_definitions:
- <Subject 1>: 唐糖，24 岁中国女性，棕色长发中分披肩... 完全参照 <Picture 1> 外观。
```

**原因**
- `<Picture>` 职责 = 定义**具体画面**（首帧 / 尾帧 / 关键帧）
- `<Subject>` 职责 = 定义**可复用视觉元素**（人物 / 场景 / 服装）
- 角色图定义为 Subject 才能保持「演员身份一致性」
- 省下宝贵的 Picture 名额（上限 9），留给真正的关键帧

## 5. 场景也要定义为 Subject

纯文字描述、无参考图的场景，同样要单独定义：

```
- <Subject 4>: 夜晚街头场景，路灯、车流、店铺灯光、
  城市天际线、街道、人行道、夜晚。无参考图，由文字描述定义。
```

## 6. 去背景污染（本 skill 增强项）

参考图若带棚拍纯色背景（灰 / 白 / 黑），必须在 Subject 定义中显式否定：

```
完全参照 <Picture 1> 外观。<Picture 1> 不得展示灰色背景，
实际场景替换为夜晚街头。
```

**不写这句 → 模型大概率把灰色背景直接搬进成片。**

## 7. retention_analysis 的四个关系标记

| 关键词 | 中文 | 使用场景 |
|--------|------|---------|
| `fully_preserved` | 完全保留 | 外观 / 身份与参考图完全一致，不能有任何改变 |
| `partially_preserved` | 部分保留 | 保留主要内容，允许改变部分特征 |
| `attribute_transfer` | 属性转移 | 将参考特征转移到另一个可识别的目标主体上 |
| `weak_reference` | 弱参考 | 仅保留宽泛的风格、类别或氛围 |

### 写法模板（本 skill 增强：加动作链）

```
<Subject 1>：fully_preserved 唐糖全套外观，动作：挽着林浩的胳膊一起走路。
<Subject 2>：fully_preserved 林浩全套外观，动作：和唐糖一起并肩走路。
<Subject 3>：fully_preserved 夜晚街头场景（路灯、车流、店铺灯光、城市天际线、街道）。
画面里只有唐糖、林浩，绝对没有其它人。
```

- 保留标记用**英文**，后面直接接**中文**说明，不用 `-` 分隔
- 动作链用 `动作：A → B → C` 概括该主体的时间线

### 末尾那行「防乱入」约束

最后一行「画面里只有 XX，绝对没有其它人」严格说属于**画面构成**，
官方建议放 `detailed_description`。

**但实战中放在 retention_analysis 末尾，作为「防乱入」强约束效果更好** ——
本 skill 保留这个写法，并在校验器里标为 INFO 而非警告。

# 10 · 提示词工程纪律层（官方 sd25-pe 强化规则）

本文件把字节官方 **`sd25-pe` Prompt Optimizer** 技能中、而通用写法指南未强调的**硬性纪律**集中收录。这些规则直接决定成片是否「跑偏」，建议在任何任务进入模板前先过一遍。

> 来源：字节官方 `sd25-pe` 技能（arkdocs.tos-cn-beijing.volces.com/skills/sd25-pe，skill_version 0.1.0，2026 年发布），与《Seedance 2.5 提示词指南》同源且更严格。本技能已将其整合为纪律层，模板仍见 01–09。

---

## 一、不可违反的 11 条原则

1. **意图优先**：不得改变人物身份与数量、关键道具、场景、事件因果、空间关系、编辑对象、延长方向和故事结果。
2. **模板优先**：无论原 Prompt 是否完整，都要进入当前任务对应模板重新组织，不能只做同义改写。
3. **素材逐份负责**：每份实际使用的素材说明采用什么；实际可用但未分配职责的素材必须逐个列入 `【未采用素材】`，阻止后续 PE 重新激活。
4. **用户映射优先**：用户明确指定的素材职责、主体名称和关系不得被自动判断覆盖；已覆盖对应槽位时，不得为增强同一职责再添加未点名素材。
5. **最少澄清**：能从文字、素材和上下文合理判断的内容直接完成，只对会改变核心结果且存在多个等价解释的问题合并询问一次。
6. **只写可提交内容**：Prompt 内不得出现分析过程、评测说明、实验分组、模型版本、运行标记、接口密钥或修改理由。
7. **参数分离**：画幅、总时长、分辨率、帧率和声音开关不写进 Prompt。普通生成由页面/接口设置；视频编辑、首帧/首尾帧、视频延长先遵循各自自动锁定规则（见 04）。用户写出的事件时间段属于创作内容，不得仅根据目标时长反向生成新数字时间段。
8. **不滥加约束**：不得自动添加用户未要求的画质包、稳定包、水印、Logo、字幕、分身或其他通用负向约束。
   > **调和注记**：[01-core-formula](01-core-formula.md) 写崩点表「加 `不要字幕。`」仅限三类场景——① 用户提出字幕/文字控制需求；② 画面必含文字元素需防误读；③ 生成结果已出现莫名字幕需事后排除。**不构成"默认添加字幕排除句"的依据**，与本节原则 8 一致。
9. **单一最佳版本**：默认只输出一个最合适的 Prompt；用户明确要求对比版时才输出多个。
10. **事实与观察分离**：人物身份、年龄、关系、事件和结果以用户文字为准；素材只补充直接可见/可听的属性，不把视觉猜测升级为剧情事实。
11. **主体基数匹配**：单人设定图不得同时定义两个会同时出场的命名人物；多个可用单人候选先一人分配一图，多个可用群体候选先一组分配一图；只有同一主体多视角、或素材本身明确含同一故事群体时，才允许合并参考。

## 二、输入状态判断

进入模板前先判定输入属于哪种状态：

- **纯文生视频**：无素材、文字也未表达参考需求。直接提取主体/事件/场景/视觉/镜头/声音套用生成模板。不得虚构素材编号，也不得建议补素材。
- **需要参考但未提供素材**：用户提到「参考这个人」「沿用原视频」但输入里没有对应素材。仍按文字输出最佳 Prompt，不阻塞；最多在 Prompt 外补一条建议说明提供该素材后可进一步映射。
- **素材可读取**：主动读取用户提供的图/视频/音频，先盘点全部素材再建映射。不靠文件名猜测，也不强制把所有素材写进 Prompt。
- **当前环境无法读取**：用户给了附件/路径/URL 但读不到。不得假装已看素材；继续优化文字可确认部分并说明哪些读不到。只有不可访问内容是唯一核心主体/唯一编辑母版/唯一延长源视频时，才请求访问方式。
- **素材规格预检**：先区分硬上限与推荐范围（见 02 上限表）。超过硬上限时优先保留用户指定/必需实体/唯一母版或源视频/关键帧素材，其余不写入 Prompt 并加一条 `素材提示：`；不得声称仅靠 Prompt 能绕过上限。

## 三、故事合同与内部核对表（不输出给用户）

1. **故事合同**：从用户文字锁定主体及数量、动作事件因果、场景时空天气、道具归属交接、视觉/镜头/声音需求、用户要求保持或排除的内容、任务类型。它是改写的事实边界——不得因素材里出现更醒目的人物/服装/场景就替换、合并或删除合同中的角色与事件。
2. **镜头/素材编号语义**：`镜头45`、`镜头 45`、`Shot 45` 默认是镜头编号，不是「45 度机位」；只有用户明确写「45 度」才是机位角度。不得把镜头编号、素材编号、章节编号改写成摄影参数。
3. **对白账本**：只要输入含说话/对白/旁白/音频职责，就为每个时间段建内部账本，记录说话人、是否发声、台词原文、音频职责、画内/画外位置。不得把已指定说话/音频的片段改成静默，也不得交换说话人与音频。用户要求某角色说话并绑定音频但无台词文字或无法听写时，保留该角色使用对应音频说话的职责，不编造台词。
4. **用户只给带引号台词片段/关键词**：只把该片段作为可说原文，可补表情/动作/语气，但不得补写前后不存在的完整句子。用户只描述说话意图（「用身份压人」「继续争吵」）无原文时，不编造对白，改用可观察口型/停顿/姿态/对方反应表达。
5. **必需实体清单**：把每个明确出现的人物/群体/关键道具/场景列为一个内部槽位（不输出），后续为每个槽位记录剧情职责、采用素材、可观察特征；输出前确认每个槽位均已进入 Prompt。
6. **内心活动外化**：转成可见动作、表情、台词或旁白，但不得增加改变故事的事件。
7. **因果揭示镜头**：先呈现触发原因再呈现人物反应；原因与反应较远时用一次明确视线/镜头转移建立关系，能同框则同构图保留两者。不得过早推纯面部特写，也不得只给反应特写而漏触发原因。
8. **假装受伤/险情**：歧义镜头中明确保持未受伤可观察状态（皮肤/服装/道具完整），不得把表演或未发生事件改写成真实伤口/流血/破损。

## 四、素材映射纪律

### 4.1 映射优先级（固定顺序）

```text
用户明确指定 > Prompt 中的描述 > 素材内容 > 文件名和元数据 > 上传顺序
```

用户明确映射已覆盖全部必需实体时，未被点名的其他可用素材默认**不激活**；不得仅因内容相似就补成第二人物/第二场景/辅助参考，也不得为增强同一职责再添加未点名素材。泛称背景宾客/家具/装饰/环境元素不构成素材缺口。

上传顺序通常只用于生成稳定编号，不是身份/职责证据；只有用户要求直接输出且候选同等合理、槽位数量=候选数量时，才作为平局规则一对一分配，且只解决分配稳定性、不证明真实身份，也不得据此添加年龄/关系/性格。

### 4.2 故事分配 vs 素材观察

- **故事分配**（来自用户文字）：人物叫什么、年龄关系、承担事件、道具归属、结局。
- **素材观察**（直接可见/可听）：五官、发型、服装、材质、颜色、空间布局、动作、运镜、音色。

素材只补充可观察特征；不得从外观反推或改写文字中的身份/年龄/关系/剧情；无法确认的品牌/颜色/职业/性格/道具功能不得擅自补写。用户只称「人物/主体」时沿用中性称谓，不得擅改称为舞者/工人等；人物素材默认只写五官/发型/服装/配饰与可观察姿态，不用「少女感/强势气质」等总结标签代替可见特征（用户明确要求表演方向时再改写为表情/姿态/动作）。

### 4.3 `【未采用素材】` 协议（强制）

只要存在实际可用但未分配职责的素材，就在素材职责之后增加 `【未采用素材】`，按媒体类型逐个列出未采用编号，并明确它们不用于人物/场景/道具/动作/镜头/声音。不得只在 Prompt 外说明，也不得用「其他素材」代替具体编号。

```text
【未采用素材】
@图片5、@图片6未参与本任务，不用于人物、场景、道具、动作或镜头。
@音频2未参与本任务，不用于台词、音色、环境声、音效或音乐。
```

> 当前环境无法取得完整素材清单时，不得编造未采用编号。

### 4.4 主体基数匹配

- 单人设定图不得同时定义两个会同时出场的命名人物。
- 多个可用单人候选：先一人分配一图；多个可用群体候选：先一组分配一图。
- 只有同一主体多视角，或素材画面本身明确含同一故事群体时，才允许合并参考。
- 一行只定义一个主体/群体/道具/场景及其主参考；禁止把多个主体和多个素材压进同一句范围映射（如「人物A和人物B参考@图片1、@图片2」应拆成两行）。
- 同一主体多份参考：分别说明每份补充的视角/属性，并声明共同定义同一实体、不生成多个副本。
- 用户已明确某编辑对象采用 `@图片3` 时，即使其他图片更清晰或相似，也不得把未点名图片追加为该对象外观/服装/群体/辅助参考；这些素材继续列入 `【未采用素材】`。

### 4.5 空间站位

围绕门、桌、车、柜台、道路等稳定物体描述内外/前后/朝向/距离/隔挡，不要只写屏幕左/右。例如：`店员始终站在玻璃柜台内侧，身体朝向柜台外；顾客A和顾客B并排站在柜台外侧，隔着柜台与店员交谈。` 用户提供干净站位图时用于构图/位置/朝向/空间关系，但不把图中的箭头/标注框/说明文字当作成片内容。

### 4.6 置信度处理

- 高置信度：自动映射并继续。
- 中置信度：采用最合理映射，在 Prompt 外「素材理解」披露关键假设。
- 低置信度但不影响核心结果：不使用该素材、不询问。
- 低置信度且影响核心身份/数量/道具归属/前后左右朝向/编辑对象/唯一母版/延长方向/关键帧职责：合并成一个简短问题。
- 发现用户明确映射与素材明显冲突时仍以用户映射为准，仅当几乎必然导致错误结果才确认一次。
- 需要澄清时只提一个整合问题并停止等待，不同时输出可能误导的临时 Prompt；用户明确要求先按假设给版时才采用假设并在 Prompt 外披露。

## 五、视频编辑强化规则（配合 04）

1. **原视频主体盘点**：画面编辑先逐一盘点原视频所有可见主体类别，包括用户点名与未点名的人物/真人/模型/动物/道具/前景/背景主体；为每一类明确写出替换/删除/保持原样。不得漏掉未点名真人/模型/道具/背景主体。用户未要求处理的对象默认保持原样；只有用户明确要求整组替换或目标画面只保留指定对象时，才把对应整组纳入删除/替换。
2. **范围闭环（每条编辑 Prompt 必备其一，不能省略）**：
   - 局部修改：`除以上明确修改对象外，@视频1中其他可见人物、道具和背景元素保持原样，不参与替换或删除。`
   - 只保留目标对象：`除以上明确保留对象外，删除@视频1中的其他可见主体；不新增未指定对象。`
3. **无法完整查看原视频时**：明确写完用户指定的替换/删除/保持对象后，加兜底句（上句局部修改版）。若用户要求只留指定对象，则把兜底改为按用户要求删除其余。
4. **跨类别动态主体替换（运动槽位覆盖）**：明确删除原主体，让目标主体继承原主体完全相同的出现时机/运动路径/速度/遮挡位置，并声明成片中不再出现原主体：
   ```text
   删除@视频1中经过<前景主体>前方的<原动态主体>，在完全相同的出现时机、运动路径、速度和遮挡位置替换为@图片1定义的<目标动态主体>。成片中不再出现<原动态主体>。
   ```
5. **时间线继承**：默认先使用全局母版继承；只有原视频中抓取/交接/放置/进出场能准确观察时，才增加少量可观察事件条件（`只有当<事件A的可观察完成状态>出现后，才发生<事件B>。`）。不要凭印象把原视频改写成时间段，也不要据不完整抽帧补写事件条件。

## 六、视频延长强化规则（配合 04）

1. **单一实例与拓扑（必须写进最终 Prompt，不能只在内部分析）**：同一主体始终只有一个连续实例，不得复制/分裂/生成第二个相同主体；保持身体结构、部件数量和拓扑关系与边界帧一致；主体转身/遮挡/出画再入画仍视为同一连续对象，不能用新实例替代。
2. **边界连续**：向后延长首帧承接尾帧、向前延长尾帧衔接首帧，逐项保持主体姿态朝向/道具位置/背景空间/机位构图/光线/声音状态/运动趋势连续。
3. **方向缺失需澄清**：用户只说「延长」且无法判断方向时，方向属高影响信息，合并确认一次。
4. **延长只创作边界之外的新片段**，不编辑原视频内容；边界目标是画面与声音自然连续，不承诺像素级相同，延长片段音量可能与原视频轻微差异。

## 七、输出合同（交付格式）

- **输出语言跟随用户**；保留用户现有素材引用形式（`@图片1` / `@Image 1` / 环境等价标签），不擅自翻译或重新编号已明确引用。
- **默认只输出优化后的 Prompt 正文**：不得加 Markdown 标题、代码围栏或前后说明，也不得输出「优化后提示词」「素材理解」「优化说明」等包装；不要求模型用代码围栏包裹结果。Prompt 自身需要结构化时可保留 `【生成目标】`/`【参考素材职责】`/`【事件脚本】`/`【保持一致】` 等任务内标签（属可提交正文，非回答包装）。
- **自动推断映射不单独输出推理表**：把最终映射直接写入 Prompt 素材职责段，每份实际使用的素材逐条说明采用范围；能读取完整素材清单时必须追加 `【未采用素材】`。
- **部分素材缺失**：先输出不再引用缺失编号的完整 Prompt 正文，再最多追加一条 `补充建议：` 单行建议（另起一行，不得接在正文最后一句后，不得拆多条，不得声称看过缺失素材）。
- **输入/参数提示**：素材超硬上限时先输出基于已选素材的完整 Prompt，再追加一条 `素材提示：` 列需缩减的素材；用户要求设置已自动锁定的参数或首尾帧画幅不一致时，先输出完整 Prompt 再追加一条 `参数提示：` 说明冲突规则与提交前动作（不重复 Prompt、不扩展成接口说明、不写回 Prompt）。
- **能力边界**：精确字幕/公式/标牌/产品参数/帧级时间点无法仅靠 Prompt 完全保证；确有必要时在正文后最多追加一行 `补充说明：` 指出需结合准备素材或后期处理。无必要则不输出任何说明。
